## 수령 처리와 안전 범위

ZZ 원본 흐름은 조회 → 로컬 지급 → 수령 ID 확인 → SAVEDATA → SAVE_MERCENARY다.
서버는 인벤토리/GP를 별도로 더하지 않는다.

- 조회: 회차·캐릭터·참여일/최종순위로 자격을 검사한 뒤 영구 opaque receipt ID를 부여한다. 최대 32행.
- 요격 수렵단 type 7은 GR 기존 12행과 별도 HR 대체 10행을 사용하며, 현재 수렵단/랭크/실제 에리어 및 출발 수렵단으로
  검증된 본인 개인 요격 점수 1점 이상을 잠금 후 검사한다. type 5 분기 보물은 해당 분기
  미완료 시점에 실제 기여한 개인으로 더 제한한다. 종류 5/7의 최초 발급 수렵단을 회차별로 고정한다.
- 종류 7은 최초 발급 시 에리어 단계별 HR/GR 묶음을 고정하여 승급 중복을 막는다.
  기존 미수령 보수와 저장 완료 이력은 보존한다.
- 지도 보수는 0054 cutover 이후 새 실제 요격 회차부터 적용하며 과거/진행 중 실적에 소급하지 않는다.
  type 5/6/7은 다음 실제 요격전 시작 전까지 수령 가능하다. 지도 전환만으로 이미 얻은 보물을 없애지 않는다.
- 수령 확인: 소유권·종류·ID를 검사하고 세션에 대기시킨다. 이때 지급 완료로 표시하지 않는다.
- 소재: SAVEDATA 저장 트랜잭션에 해당 소재 receipt만 소비한다.
- GP: GP 잔액 저장 트랜잭션에 해당 GP receipt만 소비한다.
- 저장 실패: 해당 receipt는 미수령으로 남는다. 연결 중 재조회는 저장 완료 전 차단하여 중복 로컬 지급을 막는다.
  재접속하면 DB에 저장되지 않은 보수만 다시 제시한다. 이미 확정된 ID의 확인 재전송은 무해하다.
- 이는 일반 클라이언트의 저장 실패 복구이며, 클라이언트가 임의로 조작한 저장 데이터를 완전히 검증하는 보안 기능은 아니다.

## 보류한 부분

- **40회 원본 지도·보물표:** 여전히 미확보다. 승인된 대체 지도/보물과 기존 12행 수령 연결로
  이를 원본 복원 완료로 표시하지 않는다. 개인 21행과 수렵단 12행 모두 과거 JSON 누적치로 소급 지급하지 않는다.
- 선율 최대 5/6/7/8/9/10은 누적 한도와 계정 공유 재화다. 일반 아이템으로 지급하지 않는다.
- 특별 수렵단방 1에리어 해금은 아이템이 아니다. 가영 기간·현재 수렵단 회원에 따른 정보 플래그와
  남은 에리어 조회는 구현/테스트했지만 실제 입장 성공은 미검증이다. 옛 20/25/30에리어 이용권을 중복 추가하지 않는다.
- 수렵단 28/30/32에리어 7행은 후기 독립 화면이 없어 약 65%로 평가하여 제외했다.
  후속 블로그 감사에서 25회와 28회의 독립 화면 일치를 확인했지만, 후기 유지
  근거는 추가되지 않아 보류했다. 상세 출처는 [블로그 대조 기록](diva-blog-reward-audit.md)에 있다.
- 기도 개인 달성 전체, HR 매일 보수, 수렵단 랭킹, **원본 지도 보물**은 70% 기준을 충족하는 전체 수량·조건이 없다.
  C크로와 생산권도 수량·랭크 조건 미확정이라 제외했다.

DB 마이그레이션과 단위·격리 DB race 테스트는 수행했다. 실제 인게임 수령 UI·지도·특별방·
저장/재접속 검증은 아직 필요하다. 선율 잔액/교환은 이번 지도 연결로 완성되지 않으며 여전히 비활성이다.
운영 DB 변경·배포는 수행하지 않았다.
