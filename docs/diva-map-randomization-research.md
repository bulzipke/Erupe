# 요격전 지도 페이징과 랜덤 생성 전 조사

2026-09-23. 추가 라이브 서비스 화면, 공식 매뉴얼, 당시 플레이 설명과 HD 클라이언트를
대조한 기록입니다. **조사·설계 문서이며 새 생성기를 구현하거나 운영 지도/DB를 바꾸지 않았습니다.**
위 문장은 조사 당시 상태입니다. 이후 사용자 승인으로 `custom-random-v2` 생성기를 추가했으며,
신규 실제 회차부터의 적용 조건과 유지되는 수치는 [운영 안내](diva-map-operation.md)를 따릅니다.
아래 미확보 항목이 구현만으로 원본 확정으로 바뀌는 것은 아닙니다.

## 추가 화면이 보여 주는 것

사용자가 제공한 같은 수렵단 `TRINITY・SEVEN`의 두 화면을 비교했습니다.

| 화면 | 누적 획득 에리어 | 시작과 목표 | 전선 점수/페이지 표시 |
| --- | ---: | --- | --- |
| 전가의 장 5일차 | 9 | 상단 중간 시작, 오른쪽 아래 목표 | 2,004 / 3,850 |
| 전가의 장 8일차 | 20 | 왼쪽 아래 시작, 오른쪽 중간 목표 | 0 / 5,500, 이전 페이지 화살표 |

첨부 식별자는 각각 `codex-clipboard-ce624655-e486-456c-b311-c8d2ecb3ac37.png`,
`codex-clipboard-c556f2be-eed4-472f-8cf4-a99c379b2863.png`입니다. 실제 개최 회차·촬영일은
확인되지 않았습니다. `5日目`/`8日目`는 개최 일차이지 지도 번호가 아닙니다.

- 앞 지도를 완료하고 새 지도로 넘어갔다는 해석과 잘 맞습니다.
- 이전 목표가 오른쪽 아래이고 다음 시작이 왼쪽 아래이므로, 옆으로 이어지는 배치와도 맞습니다.
- **첫 지도만 내부에서 시작하고 이후에는 가장자리로 연결한다**는 가설을 배제하지 않습니다.
- 그러나 한 쌍으로 모든 후속 지도의 시작 위치, 연결 높이, 회차 공통 배치를 확정할 수는 없습니다.
- 따라서 앞서 제안한 모든 지도의 '왼쪽 아래 시작 / 오른쪽 위 목표' 고정 조건은 채택하지 않습니다.

## 웹 자료의 범위

### 공식 확인

[서비스 종료 직전 공식 매뉴얼 page399](https://web.archive.org/web/20191218054658id_/http://cog-members.mhf-z.jp/sp/manual/page399.html)
본문에서 다음을 확인했습니다.

- 약 1시간마다 진행과 에리어 획득을 갱신합니다.
- 현재 지도의 몬스터 점거지를 모두 획득하면 다음 갱신 때 새 지도로 넘어갑니다.
- 초과 점수로 새 지도의 에리어까지 획득하지 않습니다.
- 분기 점수는 해당 분기에 반영하며 메인 진행에는 쓰지 않습니다. 분기 에리어도 달성 수에 포함됩니다.
- 새 지도로 넘어가면 이전 지도의 미획득 분기는 더 진행할 수 없습니다.
- 보물은 노랑·빨강 2종이고, 빨강은 획득 전 내용 비공개입니다. 획득 후 아이콘도 별도로 바뀝니다.

본문에는 첫 지도 시작 좌표, 페이지 사이 거점 연결 좌표, 원본 템플릿 수·선택 확률이 없습니다.

### 당시 수렵단의 설명

[荒野に舞う渡り鳥, 2017-05-16](https://ameblo.jp/kouyanimau/entry-12275262644.html)은
20·40에리어 등을 페이지 경계로 설명하고, 경계에서 초과 점수가 버려진다고 적었습니다.
이번 '획득 20 / 새 지도 0점' 화면의 해석을 보강합니다. 다만 분기 추가 전의 설명이므로,
분기 에리어까지 포함된 후기 총합에 무조건 `20으로 나눈 몫`을 적용하면 안 됩니다.
당시 글의 갱신 간격은 2시간입니다. 최종 공식 매뉴얼의 약 1시간과 시대를 구분하며,
이 글을 이유로 현재 정산 주기를 바꾸지 않습니다.

[sonouchiyameru, 2017-07-13](https://sonouchiyameru.blog.fc2.com/blog-entry-121.html)은
분기를 이용하기 전에 메인 지도를 넘겨 버리지 않도록 갱신을 기다리는 플레이를 설명합니다.
페이지 단위 진행의 참고이며, 첫 지도와 후속 지도 좌표 관계의 증거는 아닙니다.

[実際のプレイ記録, 2019-03-29](https://mhfshinko.blog.fc2.com/blog-entry-803.html)에서도
두 번째 페이지로 넘어가기 직전에 멈추어 단원의 보물 분기 진행을 기다린다는 설명을 확인했습니다.
페이지 전환의 교차 근거이지, 첫 지도 시작점이나 후속 지도 좌표표는 아닙니다.

[당시 위키](https://w.atwiki.jp/giurasu/pages/1392.html)도 페이지 전환과 이전 분기 제한을
탐색하는 데 사용했습니다. 위키의 요약이나 다른 서버의 생성기를 원본 좌표표로 간주하지 않습니다.

### 공개 생성기와 숫자 두 개의 일치

[Re-Nest 공개 개발 코드](https://github.com/Re-Nest/Erupe/blob/6b32e36aa4ebfee1153e2049b48ebd043af2824c/server/channelserver/handlers_diva.go#L797)를
다시 읽었습니다. 첫 지도 10번째 획득 대상의 식 `2500 + 150 * 9 = 3850`과
두 번째 지도의 시작 임계값 `5500`은 이번 두 화면과 일치합니다.

첫 화면이 첫 지도이고 획득 9가 메인 9개라는 가정하에 성립하는 비교입니다.
**두 숫자의 일치는 전체 점수식·5개 템플릿·랜덤 생성법·40회차 원본을 검증한 것이 아닙니다.**
이 코드의 시작/목표는 각 지도마다 별도로 무작위 선택하고, 보물에는 임시 2,000 GP라는 주석도
있으므로 그대로 이식하지 않습니다. 운영 중인 점수·보수도 변경하지 않습니다.

## 클라이언트에서 확인한 페이징

주소는 `mhfo-hd.dll.clean.mapped.bin` 기준입니다. 다른 버전의 고정 주소로 사용하면 안 됩니다.

- `11536390`: 지도 상태 저장소는 `0xe10 = 2 * 0x708`, 현재·이전 상태 두 개입니다.
- `103a90b0`: 페이지 상태 2/3에서 선택자를 0/1로 바꾸고 `103b98b0`으로 해당 상태를 구성합니다.
- `103a5a40`: 현재 지도 왼쪽 경계를 넘으면 커서 열을 11로, 이전 지도 오른쪽 경계를 넘으면
  0으로 옮깁니다. 커서 행은 유지됩니다. 옆으로 이어지는 듯한 탐색은 실제 클라이언트 동작입니다.
- `103a4990`: 현재 페이지에서 이전 화살표, 이전 페이지에서 현재 화살표를 표시합니다.
- `103a8470`: 과거 지도가 더 있어도 이 화면의 페이지 수는 최대 두 개로 제한합니다.
- `103b97b0`: `NextTemplateID`를 역추적해 과거 존재를 판단합니다. 자기 링크는 상태의
  지도 번호에서 1을 뺀 값을 사용합니다. 최대 8개 정의가 과거 8페이지 열람을 의미하지 않습니다.

각 페이지는 자체 5행 x 12열 좌표로 다시 구성됩니다. 조사한 페이지 전환 경로에는 이전 목표의
좌표로 다음 시작을 강제하거나 거대한 전역 지도 좌표로 변환하는 처리가 없습니다.
**이는 원본 서버가 두 페이지의 끝/시작 높이를 맞췄을 가능성을 반박하지 않습니다.**

## 육각 격자 연결

`103a4d00`에서 열이 1부터 시작할 때 홀수 열이 반 칸 아래로 내려가는 배열을 확인했습니다.
화면 좌표는 공통 오프셋을 제외하면 `x=(열-1)*dx`,
`y=(5-행)*2*dy + (홀수 열이면 dy)`입니다.

좌표 `(r,c)`의 이웃은 다음과 같습니다. 범위는 행 1..5, 열 1..12입니다.

- 같은 열의 `r-1`, `r+1`.
- 홀수 열이면 인접 열 `c-1`, `c+1`에서 행 `r`, `r-1`.
- 짝수 열이면 인접 열 `c-1`, `c+1`에서 행 `r`, `r+1`.

이는 안전한 기하학 연결을 검사하는 기준이지 원본 경로 생성 알고리즘이 아닙니다.

## 생성 구현에 반영할 경계

1. 첫 지도와 후속 지도의 생성 정책을 분리합니다. 아직 모든 지도를 좌하단 시작으로 고정하지 않습니다.
2. 후속 지도의 왼쪽 입구를 이전 오른쪽 출구와 이어 보이도록 배치하는 것은 유력한 후보입니다.
   보편적 원본 규칙으로 단정하지 않고 추가 연속 화면과 대조할 수 있게 분리합니다.
3. 지도 전환은 목표 획득 후 정산에 따릅니다. 날짜 변경·UI 조회·재접속 때 지형을 다시 뽑지 않습니다.
4. 동일 회차·지도 번호의 지형을 고정하고 현재/이전 페이지 각각의 정의와 진행 상태를 제공합니다.
5. 기존 `custom-v1` 저장 지도, 출발 귀속, 점수 원장, 보수 영수증을 재작성하지 않습니다.
   새 생성기 버전의 적용 경계를 별도로 정해야 합니다.
6. 보물 좌표 `407/106` 고정 검증을 과거 지도의 실제 분기 검증으로 바꿔야 합니다.
   지형 배열만 무작위로 바꾸면 기존 미수령 보물과 페이지 조회를 깨뜨릴 수 있습니다.
7. 좌표 중복·육각 이웃·Next 순서·고아 분기·페이징·재시작 재현성·과거 보수 유지 테스트를 마련합니다.
8. 원본의 분기 개수/길이, 보물 분포, 지도별 모든 임계값은 미확보입니다. 지형과 보수·난이도 변경을
   묶지 않고, 현재 대체 보수의 수량·자격을 임의로 확대하지 않습니다.

추가로 가장 유용한 자료는 같은 수렵단의 **첫 지도 완료 직전 → 두 번째 지도 → 세 번째 지도**
전체 화면입니다. 목표와 다음 시작의 행·열, 누적 에리어, 전선 임계값이 함께 보여야
첫 지도 특례와 후속 연결 가설을 더 검증할 수 있습니다.
