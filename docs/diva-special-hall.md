# 특별 수렵단방: 실제 입장 경로

## 네트워크 방과 렌더링 맵은 다릅니다

ZZ clean mapped 클라이언트의 읽기 전용 분석에서 다음 경로를 확인했습니다.

1. `11585ea0`은 수렵단방 stage 이름을 `sl<slot>Gs202p0a0u<guild-base32>`로 구성합니다. 일반/특별방을 구분하는 인수나 다른 stage 번호는 없습니다. 숫자 202(`0xCA`)를 고정 사용합니다.
2. `11554070`은 같은 stage 이름으로 `11582ba0`(create), `11583620`(enter)를 실행합니다.
3. 입장 상태 머신 `10709110`의 후속 단계에서 `11555500`이 실제 렌더링 맵을 고릅니다.
4. 개최 기간 검사 `1039ce00`과 INFO_GUILD 캐시의 특별방 플래그 `DAT_1e505968`가 모두 참이면 맵 `0x1BD`(445)를 반환합니다. 그렇지 않으면 일반 수렵단방 등급별 맵을 반환합니다.

따라서 특별방만을 나타내는 가상의 `Gs445` 권한 검사를 추가하면 실제 정상 경로에는 작동하지 않습니다. 모든 `Gs` stage에 특별방 자격을 요구하면 일반 수렵단방까지 막습니다. `handlers_stage.go`는 변경하지 않습니다.

## 서버 이용권

기존 `INFO_GUILD`의 `divaGuildSpecialHall` → `GetDivaSpecialHall` 플래그가 위 실제 입장 분기에 연결됩니다. 별도 클라이언트 패치가 필요하지 않습니다.

- 요청자의 현재 승인된 수렵단과 조회 수렵단이 같아야 합니다. 가입 신청자/미가입자는 제외합니다.
- 실제 요격 회차의 획득 에리어가 1개 이상이어야 합니다. 개인 기여나 아이템 수령은 이용 조건이 아닙니다.
- 가영의 장 시작 이상, 종료 미만인 실제 기간에만 활성화합니다. 요청 대기 중 경계가 지나면 잠금 뒤 DB 시각으로 다시 판단합니다.
- 특별방 이용권은 아이템 type 28입니다. 공식 설명처럼 달성에 따라 자동 교체되며, 목록에서 수령 버튼을 누른 기록을 추가 조건으로 삼지 않습니다.
- 정보 조회/수령 화면의 데이터가 실제로 갱신되는 시점과, 이미 입장한 클라이언트가 기간 종료 즉시 방을 다시 로딩하는지는 별개입니다. 서버는 강제 추방을 추가하지 않습니다.

## 추가 혜택 범위

공식 보존 설명상 특별방은 일반방을 대체하며 레벨 3 상당 기능, 추가 티켓 교환, 방 전체 노래 효과, 요리 및 모험 지원 등의 혜택이 있습니다. `107e1070`, `107dfee0`은 낮은 일반방 랭크를 특별방 기간/플래그로 우회하는 진입 조건도 확인해 줍니다.

푸기 추가 3바이트는 별도 검증됐습니다. `11516e90`이 INFO_GUILD의 두 번째 복장 3바이트를 별도 캐시에 저장하고, `107fcb10`/`107fddf0`이 맵 445에서 사용합니다. `115547d0` → `11551a60`의 `snj_db_set_pigcloth_tactics` 요청은 일반방 복장 변경과 다릅니다. 기존 서버가 일반 복장을 복사하고 해당 변경 요청을 누락하던 부분을 별도 특별방 복장 저장 경로로 보완했습니다. 특별 푸기 이름은 클라이언트 고정 문구입니다. 단장 권한·복장 ID·보존 규칙은 [특별방 푸기 구현](diva-special-pugi.md)을 참조합니다.

선율 수령·잔액·교환도 기존 상점 동선에 연결했습니다. 후속 복원으로 품목은 76종이며, 공식 품목명·가격과 일부 역사 자료에서 추론한 수량은 [카탈로그 복원](diva-melody-catalog-restoration.md)에 구분했습니다. [선율 구현 및 프로토콜 한계](diva-melody-implementation.md)를 참조합니다.

무료 노래는 내장 도움말(`mhfpac.csv` 1285780~1285828)에서도 현재 방 전원 적용, 중간 입장자 제외, 재청취 시 시간 갱신, 천뢰 기주 소비 없음이 확인됩니다. 실제 다중 클라이언트 발동은 인게임 확인이 필요합니다.

모험 등록은 [특별방 모험](diva-special-adventure.md)의 권한 검사에 연결했습니다. 실제 맞이의 장 기간·정식 단원·획득 에리어 1개 이상을 같은 DB 트랜잭션에서 검사한 뒤 1시간 귀환으로 등록합니다. 일반방의 6시간 모험과 이미 출발한 모험의 수령은 유지합니다.

[요리와 티켓 교환 조사](diva-special-cooking.md)에서 특별방 요리 판정 영역을 두 배로 만드는 클라이언트 원래 분기(`107f5310`)를 확인했습니다. 완성된 요리 ID·성공도를 서버가 그대로 보관합니다. 요리 생성 SQL의 자료형 충돌은 수정했으며, 추가 성공도 조작이나 이중 재료 차감은 하지 않습니다. 무료 노래와 티켓 교환을 포함한 [실제 게임 확인표](diva-player-validation.md)도 별도로 제공합니다.

기존 권한 테스트: `TestInfoGuildDivaSpecialHallFlag`, `TestDivaSpecialHallPeriodBoundaries`, `TestRepoDivaSpecialHallCurrentMembershipAndWelcomeOnly`. 원작 종료 후 모든 부가효과의 실제 플레이 검증까지 완료했다는 의미는 아닙니다.
