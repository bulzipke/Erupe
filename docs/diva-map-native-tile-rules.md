# 원본 특수 타일 재조사: 표시 규칙과 서버 운영 규칙

> 최신 운영: 새 회차에 적용하는 승인된 커스텀 침공·단계별 확률은
> [지도 v3 운영 규칙](diva-map-progressive-operation.md)을 참조하십시오.
> 아래의 침공 비활성·기존 난도 유지·`DivaMapRedTreasureMode=off` 설명은
> v3 도입 전 v1/v2 범위의 기록입니다. 원본 표시 분석과 미확보 원본 수치의 구분은 유효합니다.

2026-09-23. HD 덤프를 Ghidra MCP HTTP 읽기 전용으로 확인했습니다.
클라이언트/메모리 패치 및 운영 DB 변경은 없습니다. 아래는 **네이티브 표시 의미의 복원**이며,
40회 원본 난수 생성기·침공 스케줄을 복원했다는 뜻은 아닙니다.

## 확인한 표시 계산

`103b9440`은 좌표로 정의와 상태를 매칭한 뒤 40바이트 UI 노드를 만듭니다.

| UI offset | 의미 | 원본 계산 |
|---|---|---|
| +0x06 | 기본 타일 종류 | 분기 퀘스트 3개 중 nonzero가 있으면 3; 정의 Kind 1/2는 시작/목표로 우선 적용 |
| +0x08 | 필요 점수 | 상태 RequiredPoints (시작은 0, 나머지의 0은 1로 보정) |
| +0x0C | 기본 대비 증가량 | max(상태 RequiredPoints - 정의 BaseRequiredPoints, 0) |
| +0x10 | 남은 점수 | max(상태 RequiredPoints - 상태 EarnedPoints, 0) |
| +0x24 | 보물 내용 숨김 | 정의 TreasureMode 그대로 복사 |

`103b96c0`은 남은 점수와 증가량이 모두 nonzero인지 확인합니다.
`103b88b0`의 지도 표시 타일은 다음과 같습니다.

| 조건 | 표시 타일 번호 | 원본 의미 |
|---|---:|---|
| 노드 없음 | 0 | 경로 밖 |
| 시작 | 1 | 수렵단 거점 |
| 목표, 기본 대비 증가 없음/이미 획득 | 2 | 몬스터 거점 |
| 분기 퀘스트 있음, 미획득 | 3 | 중립 지대 |
| 일반 또는 분기, 획득 완료 | 5 | 수렵단 점령지 |
| 일반, 미획득, 증가 없음 | 6 | 몬스터 점령지 |
| 일반, 미획득, 증가 있음 | 7 | 몬스터 격전지 |
| 목표, 미획득, 증가 있음 | 8 | 강화 표시된 몬스터 거점 |

UI kind 4도 분기와 같은 완료 처리가 있지만 현재 확인한 서버 응답 → `103b9440`
경로에서 이를 생성하는 조건은 없습니다. 새 타일 기능으로 임의 할당하지 않습니다.
정의 Kind 3만으로 분기용 퀘스트가 생기는 것도 아닙니다.

`103a90b0` 상세창은 획득 완료→우세, 미획득·증가 없음→열세↓,
미획득·증가 있음→열세↓↓를 선택합니다. `103a75f0`은 증가가 있을 때
필요 점수를 빨간색으로 표시합니다. **진행률이 절반을 넘었다고 우세가 되는 방식이 아닙니다.**

원문 메시지는 로컬 `dat/툴/ptrmaps/mhfpac.ptrmap.csv` slot 4016 → 1288992와
`dat/툴/mhfpac.csv`에서 대조했습니다. 상태 문구는 1289084/1289088/1289092,
몬스터 격전지 명칭은 1289124입니다. 계산과 문구가 서로 일치합니다.

## 무엇이 여전히 미확보인가

- 언제, 어느 타일의 필요 점수를 얼마씩 올리는지에 대한 원본 서버 수식.
- 원본 분기 개수/길이, 보물 배치 확률, 지도별 경로 템플릿 선택 비율.
- 원본 보물의 정확한 추첨표와 수량.
- 침공 관련 코드가 최종 40회 실제 운영에서도 사용됐는지 여부.

로컬 문자열 1289064에는 몬스터의 기세와 필요 점수 증가를 알리는 로그가,
1289204에는 다음 침공 시각 안내가 남아 있습니다. 그러나 문자열 존재만으로
시간 간격·증가량 또는 최종 서비스 사용 여부를 증명할 수는 없습니다.
[최종 공식 매뉴얼](https://web.archive.org/web/20191218054658id_/http://cog-members.mhf-z.jp/sp/manual/page399.html)은
시간별 갱신, 분기, 보물 두 종류, 지도 전환을 설명하지만 위 수치를 제공하지 않습니다.

정의 Unknown02/04/06/08/10/12, 상태 Unknown21/22를 랜덤 효과·침공 확률로
사용하지 않습니다. 조사한 UI 투영 경로에서는 그 필드가 전달되지 않습니다.

## 기존 구현에 대한 결론

현재 v1/v2 생성기는 다음 페이지부터 상태 필요 점수를 기본값보다 크게 잡습니다.
그러므로 위 클라이언트 계산에 의해 이후 지도에서 격전지/열세↓↓ 표시가 나올 수 있습니다.
이는 **기존 서버 커스텀 난도 곡선의 결과**이며 원본 시간제 침공이 실행된 증거가 아닙니다.
이번에는 저장된 필요 점수·기여·정산·원장이나 그 곡선을 변경하지 않았습니다.

노란/붉은 보물의 숨김과 획득 후 공개는 [기존 표시 구현](diva-map-special-elements.md)을
유지합니다. 원본 배치 비율은 불명이라 `DivaMapRedTreasureMode=off` 기본값도 유지합니다.
임의의 침공 타이머나 “특수 타일 효과”를 새로 만들어 원본이라고 제시하지 않습니다.
