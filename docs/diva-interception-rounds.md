# 요격전 회차별 집계 전환

2026-09-21. 기존 누적치를 보존하고 새 회차부터 별도 집계한다는 사용자 요청에 따른 변경.

## 데이터와 전환 시점

- 0046 마이그레이션은 기존 `guild_characters.interception_points` JSON을 삭제하거나 새 회차로 복사하지 않는다.
- 설치 시 이미 시작한 가희 이벤트 ID를 `diva_interception_legacy_events`에 기록한다. 아직 시작하지 않은 예약 회차는 제외하지 않는다.
- 전환 전 진행 중 회차는 기존 JSON 조회/가산을 유지하지만 새 개인 보수의 지급 근거로 쓰지 않는다.
- 새 회차에서는 `diva_interception_runs`만 합산한다. 이전 회차 실적·수령 이력은 보존하며, 다음 회차가 0에서 시작한다.
- 정상 회차 갱신은 과거 이벤트를 삭제하지 않는다. 따라서 연결된 노래 구슬 원장·보수 수령 이력도 함께 삭제되지 않는다.
- 강제 2/3단계도 날짜·재접속마다 회차가 달라지지 않도록 DB에 앵커를 저장한다. 기존 진행 중 회차가 있었다면 첫 강제 앵커도 전환 전으로 취급하고 다음 갱신부터 별도 집계를 시작한다.
- 강제 단계 변경은 새 운영 흐름으로 취급한다. 운영 중에는 단계를 수동 전환하기보다 정상 일정(`DivaOverride=-1`)으로 진행하는 편이 회차 귀속을 명확히 한다.

## 점수와 개인 보수

- 실제 퀘스트 입장과 검증된 퀘스트 설정이 모두 확인될 때 회차 ID·수렵단·출발 시각·서버 생성 UUID를 고정한다.
- 마을 복귀 후 결과가 와도 이 스냅샷을 사용한다. 다음 출발은 이전 스냅샷을 교체한다.
- 같은 회차 요격 기간에 출발·보고한 결과만 인정한다. 기간을 넘긴 지연 결과를 다음 회차에 넣지 않는다.
- 출발 UUID별로 한 번만 기록한다. 동일 결과 재전송은 점수를 더하지 않고, 같은 UUID의 다른 점수는 거절한다.
- 기록할 때 실제 정회원 여부와 출발 당시 수렵단 일치를 확인한다. 실패한 저장을 성공으로 응답하지 않는다.
- `diva_prizes`의 개인 보수 21행은 새 회차 점수/GR 조건을 만족하면 기존 소재·GP 원자 수령 처리에 연결된다. 반복 보수는 이번 표에 없으며 지원하는 것으로 가정하지 않는다.
- 미수령 개인 요격 보수는 다음 **실제 요격전 시작 전**까지 수령한다. 기도 회차가 바뀌어도 바로 만료시키지 않으며, 실제 요격 개최 기록을 기준으로 조회·새 수령 요청의 기한을 함께 검사한다. 이미 수령한 ID의 재전송은 중복 지급하지 않는다.
- 점수 자체는 기존 클라이언트가 계산해 보고하는 값이다. 이 변경은 회차 혼입과 동일 출발 재처리를 막는 것이며, 임의 변조 점수의 완전한 서버 검증은 아니다.

## 클라이언트 응답 수정

ZZ `mhfo-hd.dll.clean.mapped.bin` 역분석:

- `114fe8b0 → 11536900`: 조회는 상태 u8 + 총점 u32 + 개수 u8 + 퀘스트 ID u16 목록.
- `114fe9c0 → 11536a30`: 추가 ACK는 상태 u8 + 개수 u8 + 같은 목록.
- `103a25c0`: 완료 목록에 현재 퀘스트가 있으면 첫 클리어 보너스를 생략한다.
- `10430d40`: 같은 목록으로 완료 표시를 그린다.
- 두 파서는 기존 배열을 지우지 않는다. 최대 255칸을 항상 전송하고 남는 칸을 0으로 채워 새 회차에 이전 기록이 남지 않도록 한다.

## 아직 별도 구현이 필요한 것

수렵단 보수 12행의 조건은 완료 **에리어 수**다. 퀘스트 종류 수나 개인 점수 합계가 아니다.
현재 지도 조회/생성 핸들러가 미구현이고, `11536390`의 복잡한 지도 구조에서 노드 획득 조건·임계점·완료 수 산출까지는 확인하지 못했다.
따라서 수렵단 type 7 지급은 보류하며, 이번 변경으로 수렵단 보수까지 완성됐다고 간주하지 않는다.

운영 DB 변경/배포는 별도로 하지 않았다. 업데이트 서버의 다음 시작 때 마이그레이션이 적용된다. 실제 인게임 출발→복귀→수령→재접속 검증은 필요하다.
