# 선율 교환: 초기 역분석 기록

> 아래는 2026-09-21 당시의 보류 사유를 보존한 기록이다. 2026-09-23에
> ACK endian과 전용 보수 타입을 추가 확인하여 적립·교환을 구현했다.
> 현재 적용 범위와 남은 제약은 [선율 구현 문서](diva-melody-implementation.md)를
> 따른다. 이 문서의 "비활성/미구현" 표현은 초기 조사 시점의 상태다.

2026-09-21, ZZ `mhfo-hd.dll.clean.mapped.bin` 읽기 전용 역분석.
**실제 선율 적립·교환은 아직 비활성이다.** 아래 패킷 보완은 활성화나
지급 완료를 의미하지 않는다. 운영 DB, seed와 상품 목록은 변경하지 않았다.

## 확인된 클라이언트 흐름

| 주소 | 직접 확인한 동작 |
| --- | --- |
| `107bbcb0` | 선율 상점 조회는 `ENUMERATE_SHOP` type **9**, shop ID **0** |
| `11528fe0` / `11528af0` | 서버 상점 목록을 받아 30바이트 wire 행을 32바이트 내부 행으로 변환; 비용·아이템 ID·지급 개수를 서버 목록에서 읽음 |
| `114ff090` | `GET_UD_SHOP_COIN` opcode `0x17a`, 요청은 AckHandle만 포함 |
| `114ff190` | `USE_UD_SHOP_COIN` opcode `0x17b`, 요청은 AckHandle 뒤 **u8 비용** 하나 |
| `115372b0` / `114ed300` | GET/USE 모두 simple ACK를 기다림. ACK 해석 결과의 첫 바이트를 선율 잔액으로 사용; transport 데이터는 고정 4바이트 |
| `107bb1c0` / `107bb270` | 잔액·아이템 공간 확인 및 구매 확인 UI. USE 성공 후 `10ba1280(itemID, quantity)`로 클라이언트가 지급 |

선율 사용 요청에는 아이템 ID, 지급 개수, 회차 ID, 재시도 식별자가 없다.
서버가 별도로 같은 아이템을 지급하면 이중 지급 위험이 있다. 잔액 차감과
후속 캐릭터 저장을 원자적인 지급으로 취급할 수도 없다. 원본 프로토콜을
유지한 구현은 이 한계를 명시하고, 계정 잔액의 동시 차감·초과 차감부터 막아야 한다.

기존 파서는 사용 비용 한 바이트를 읽지 않았다. 지금은 이 필드를 읽고
잘린 요청을 거절하며, USE 거절 ACK도 native와 같은 simple 형식으로 맞췄다.
GET은 계속 0, USE는 모든 비용을 거절한다. 단순히 성공 ACK를 보내지 않는다.
0이 아닌 잔액을 활성화할 때는 ACK 수신부의 정수 endian 변환까지 추가 검증해야 한다.
현재 확인한 결과 버퍼의 바이트 위치를 wire의 첫 바이트로 단정하지 않는다.

## 계정·회차 규칙과 실제 차단 요인

[복구한 최종 공식 매뉴얼](https://web.archive.org/web/20191218054658id_/http://cog-members.mhf-z.jp/sp/manual/page399.html)
근거는 [원본 보수 조사 문서](diva-original-reward-catalog.md)의 공식 복구 절에 있다.

- 계정 내 캐릭터의 획득량을 **합산하지 않고 최댓값**을 사용한다.
- 전 캐릭터가 잔액과 소비량을 공유한다. 가영의 장 종료 시 잔액은 소멸한다.
- 포인트별 `최대 5, 6, ... 10` 보수는 추가 아이템이나 누적 합산 지급이 아니다.
- 잔액은 `(account, event)`별 최고 획득 상한에서 같은 계정·회차 소비량을
  차감하는 형태로 구현할 수 있다. 현재 그런 원장 및 차감 구현은 없다.
- 실제 교환 NPC는 특별 수렵단방에 있다. 지도/영역 확보와 방 해금이
  아직 없으므로 월렛만 만들어도 정상 플레이에서 전체 동선은 완성되지 않는다.
- 보수를 받는 행위와 선율 상한 확정의 결합 방식, HR/GR별 미확보 하위 상한도
  추가 확인이 필요하다. 미수령 상태에서 원시 점수만으로 선율을 자동 발급하지 않는다.

따라서 이번에는 상품 추가·잔액 발급·원장 마이그레이션을 하지 않는다.
지도 필요 점수를 임의로 만들어 방을 열거나, 선율을 일반 아이템으로 대신 지급하지 않는다.

그 표에는 별도 지급 개수 열이 없다. 공식 이름/비용 확인과 지급 개수 확인은 별개다.
