# 요격전 지도·분기 운영 및 확인 절차

2026-09-23. 사용자가 승인한 서버용 대체 지도를 구현했습니다. **40회 원본 지도 복원은 아닙니다.**
이번 작업에서는 운영 DB 변경, 서버 배포, 클라이언트 수정, 커밋을 하지 않았습니다.

## 적용 시점

- 지원 대상은 ZZ입니다. `DivaOverride=0` 또는 게임 시각 강제 옵션에서는 지도를 활성화하지 않습니다.
- 서버 업데이트 시 자동 마이그레이션 `0054_diva_maps.sql`이 설치 시점을 기록합니다.
  **그 이후 실제로 시작한 새 요격 회차부터** 지도 원장을 사용합니다. 현재 진행 중 회차나 과거
  개인 누적치를 에리어로 환산하지 않으며 기존 보수 이력도 삭제하지 않습니다.
- 이후 승인된 `0056_diva_current_map_activation.sql`은 업데이트 시 실제 진행 중인 최신 요격 회차가
  위 전환 규칙으로 막혀 있고 기존 지도가 없으면, **그 시점부터 지도만 0에서 시작**하게 합니다.
  이 결정은 1회만 저장합니다. 적용 때 해당 회차가 없으면 이후 회차를 소급 활성화하지 않습니다.
  이전 출발·점수는 지도에 넣지 않고, 적용 후 검증된 출발 결과만 개인 누적과 지도 원장에 함께
  기록합니다. 개인 누적 JSON·완료 퀘스트·기존 수령 이력과 개인 보수 전환 정책은 유지합니다.
  회차 시작/종료 날짜도 바꾸지 않습니다. 별도 운영 DB 작업 없이 새 서버의 자동 마이그레이션으로 적용됩니다.
- 기도의 장 고정 중에는 새 요격전이 시작되지 않습니다. 정상 일정은 `DivaOverride=-1`입니다.
  강제 단계의 기존 앵커를 지우거나 회차를 수동 조작하지 말고 적용 시점부터 확인해야 합니다.
- 지도·보물 수치에는 별도 config 키를 추가하지 않았습니다. 회차별 생성 버전과 시드는 고정하며,
  운영 도중 표를 바꾸면 기존 진행을 다른 규칙으로 해석하지 않고 오류로 거절합니다.
- `0058_diva_random_maps.sql` 적용 시점을 영구 저장하고, **그 이후 실제로 시작하는 새 요격 회차**에
  `custom-random-v2`를 적용합니다. 진행 중 회차는 아직 지도를 조회하지 않았어도 `custom-v1`을
  유지합니다. 기존 회차 행이 있으면 그 버전도 바꾸지 않습니다. 서버 재시작이나 단계 override만으로
  기존 회차의 지도 모양이 바뀌지는 않습니다. 별도 config 설정이나 운영 DB 수동 갱신은 필요 없습니다.
- `0055_diva_tactics_followers.sql`은 동행자 계약 저장소입니다. 지도와 별도 기능이며
  [동행자 분석·제한](diva-tactics-follower.md)을 따릅니다.

## 지도와 보물

기존 `custom-v1` 회차는 고정 배치를 반복합니다. 새 `custom-random-v2` 회차는 회차 생성 때
양수 63비트 시드를 한 번 저장하고, 시드와 지도 번호로 지형과 두 분기 위치를 결정합니다.
같은 회차·지도 번호는 모든 수렵단에서 같고, 조회·재접속·재시작으로 재추첨하지 않습니다.
보물 품목/수량·경로별 퀘스트·필요 점수는 두 버전이 같습니다. 몬스터는 선택한 퀘스트 데이터가
정하며 지도 칸마다 몬스터나 속성을 무작위 배정하지 않습니다.

v2의 첫 지도는 왼쪽 내부/상단 출발을 우선하며, 목표는 오른쪽 끝입니다. 후속 지도는 이전 목표와
같은 행의 왼쪽 끝에서 시작합니다(육각 열의 반 칸 엇갈림은 유지). 경로 탐색에 상한을 두고,
실패하면 검증된 안전 경로로 대체합니다. 첫 지도도 대체 경로에서는 왼쪽 끝에서 시작할 수 있습니다.
메인 20에리어와 두 분기는 각각 육각 이웃으로 연결되고 좌표가 중복되지 않습니다.
첫 지도 특례·페이지 사이 거점 연결은 사용자 화면을 바탕으로 승인한 추론이며,
원본 서버의 난수 생성 알고리즘이나 40회차 템플릿을 복원했다는 의미는 아닙니다.

현재 지도와 직전 지도는 별도 정의·진행 상태로 전송하므로 지형이 달라도 좌우 페이지를 이동할 수
있습니다. 네이티브 조회 화면에는 두 페이지만 제공하지만, 더 오래된 보물은 저장된 당시 지도와
획득/참여 원장으로 검증합니다. 기존 `407/106` 고정 좌표, 수령 키, 티켓/GP 분리 수령도 보존합니다.

메인은 시작점을 제외한 20에리어입니다. 5개씩 2,500 / 3,500 / 4,500 / 5,500점이며
첫 지도 총 80,000점입니다. 다음 지도부터 125 / 150 / 175 / 200%를 적용하고 200%에서 멈춥니다.

| --- | --- | --- | ---: | --- |
| 첫 분기 | 메인 5에리어 완료 | 58079, 58080 | 5,000 | 수렵단 티켓 5개 + GP 500 |

메인 목표 완료입니다. 둘 다 완료하면 첫 지도에서 총 22에리어를 얻습니다. 분기 점수는 해당
분기에만 넣으며 메인에는 넣지 않습니다. 개인 요격 점수는 그대로 누적됩니다.

메인 퀘스트는 기존 EventQuests seed에서 확인한 type 46/48만 허용합니다. 58043~58128의
빈 번호까지 일괄 인정하지 않습니다. 분기 type 47은 위 다섯 번호입니다. 실제 퀘스트 파일의
정상 로딩과 출발 검증도 필요하며 임의 ID 요청만으로 점수 자격이 생기지 않습니다.

보물은 원본 미확보 상태에서 **별도 승인받은 대체표**입니다. 해당 회차·지도·분기에 실제 기여한
캐릭터만 한 번 받습니다. 같은 정산 구간에 분기를 함께 완료한 파티원은 마지막 필요 점수를
누가 소비했는지와 무관하게 참여자로 인정합니다. 이미 완료된 분기나 지나간 지도에 뒤늦게
보고한 결과로 새 보물 자격을 만들지는 않습니다. 티켓과 GP는 각자의 저장 트랜잭션에서 수령 확정됩니다.

## 정산·소속·랭킹

- 서버가 확인한 출발 시점의 회차·수렵단·지도·경로·UUID를 고정합니다. 같은 결과 재전송으로
  중복 가산하지 않습니다. 동행 NPC는 별도 인간 참가자로 세지 않습니다.
- UTC+9 매시 정각을 정산 경계로 사용합니다. 경계와 같은 시각에 들어온 보고는 다음 구간입니다.
  백그라운드 작업은 분 단위로 확인하며 조회·수령도 놓친 경계를 따라잡습니다.
- 초과 지도 점수는 폐기하고 다음 지도에 넘기지 않습니다. 기존 개인 점수는 차감하지 않습니다.
  완료 지도를 이전 화면으로 보존하고, 과거 지도·회차의 늦은 결과를 새 지도에 넣지 않습니다.
- 서버 재시작 후에도 출발·기여·에리어·보물·랭킹 원장이 남습니다. 단, 재시작으로 끊어진
  플레이 중 세션을 복원하여 결과를 새로 만들어 주는 기능은 아닙니다.
- 실제 에리어 획득을 04·12·20시에 공개합니다. 종료 때 마지막 정산과 최종 순위를 고정합니다.
  동률은 1·1·3 방식, 상위 100개와 자신의 수렵단을 별도로 전송합니다.
  정각 처리·동률·즉시 최종 공개는 서버 운영 규칙이며 원본의 내부 시간을 복원한 것은 아닙니다.
- 탈퇴·이적 후에는 기존 출발의 소속을 임의 변경하지 않습니다. 보물/수렵단 보수는 첫 유효
  보수 조회 때 회차별 소속을 고정하여 여러 수렵단의 보수를 골라 중복 수령하지 못하게 합니다.

만족한 정회원 중 해당 수렵단에서 실제 요격에 참여한 캐릭터에게 지급합니다.
같은 회차·에리어 단계의 HR/GR 묶음은 최초 발급 시 하나로 고정하여 승급 중복 수령을 막습니다.
보물과 함께 다음 실제 요격전 시작 전까지 수령 가능하며 새 기도 회차만으로 만료시키지 않습니다.

특별 수렵단방은 1에리어 이상을 획득한 수렵단의 현재 정회원에게, 해당 회차의 **가영의 장 기간**에
기존 `INFO_GUILD` 이용 가능 플래그를 전달합니다. 미참여 개인도 수렵단 혜택을 이용할 수 있습니다.
남은 에리어 조회도 실제 0/1을 반환합니다. 이는 기존 클라이언트에 자격을 전달하는 연결입니다.
실제 입장·배경 전환은 아직 인게임 검증하지 않았고, 별도의 stage 입장 권한 강화까지 구현한 것은 아닙니다.
선율 교환 등 특별방의 모든 부대 기능이 완성됐다는 뜻도 아닙니다.

## 지도 조회 오류 처리

네이티브 클라이언트에서 성공 buffer ACK의 본문 `ff`는 종료 오류가 아니라 정보 재조회 경로입니다.
이용 불가/잘못된 지도에 `ff`를 주던 코드를 `01`로 바꿨습니다. `01`은 기존 오류 안내창으로
진입한 뒤 사용자 확인으로 종료되므로 서버 자동 재조회·생성 루프를 만들지 않습니다.
정상 지도 응답은 기존 `00 + 지도 본문`을 유지합니다. 상세 근거는
[패킷 분석](diva-interception-map-protocol.md)을 참고합니다.
