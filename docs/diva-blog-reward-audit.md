# 가희 보수 블로그 대조 기록

조사일: 2026-09-22. 기준은 진설 40회다. 40회 직접 확인 표의 대조 결과와,
사용자가 허용한 과거 회차 기반 보완을 구분한다. 아래 5행만 기도 GR 개인
달성 보수에 추가하며, 운영 DB 직접 변경·배포·기존 수령 이력 초기화는 하지 않는다.

## 회차를 섞지 않아야 하는 항목

- [27회 주황 깃발 보수](https://byuwasoku.hatenablog.com/entry/2018/12/20/121934)는
  해당 회차에서 보라 깃발 대신 지급한다고 명시한다. 최대 50개라는 조건을
  40회 개인 달성 보수로 확대하지 않는다.
- [30회 21,000점 기주 무기 소재](https://byuwasoku.hatenablog.com/entry/2019/03/22/172752)와
  다른 회차의 신규 소재는 회차별 무기 구성이다. 40회 기사에는 신규 기주
  무기가 없다고 명시되어 있으므로 과거 소재를 모두 누적 추가하지 않는다.
- 40회 `Ｃクロワ生産券`(0x2547)은 노래 구슬 1점의 개인 달성 보수라는 사실은
  확인되지만 지급 수량·HR/GR 범위는 아직 부족하다.
  [무기 강화 화면](https://cdn-ak.f.st-hatena.com/images/fotolife/m/machikorokoro/20191128/20191128004041.png)은
  보수 수량 화면이 아니므로 이를 지급 개수 근거로 사용하지 않는다.
- [구 1회](https://sonouchiyameru.blog.fc2.com/blog-entry-12.html),
  [구 3회](https://sonouchiyameru.blog.fc2.com/blog-entry-31.html),
  [진설 1·2회](https://sonouchiyameru.blog.fc2.com/blog-entry-61.html)의
  여러 점수에 걸친 품목별 최대 합계·GP 누적 합계를 개별 지급량이나 반복량으로 바꾸지 않는다.
  초기 GP 간격 설명도 40회 무한 지급 조건으로 확대하지 않는다.

## 단일 임계점 5행 — 과거 회차 보완 적용

누적 합계를 일괄 제외하는 것은 너무 넓은 판단이었다. **최소 점수와 최대
점수가 같은 항목**은 해당 임계점 하나에 전량 귀속되므로, 범위가 있는 품목과
구분할 수 있다. 위 세 글에서 다음 점수·수량이 동일하게 나온다. 이는 같은
저자의 연속 기록이지 독립 저자 세 명의 검증은 아니다.

| 점수 | 아이템 | ID | 수량 |
| ---: | --- | --- | ---: |
| 24,500 | 캐라반 동강석 / キャラバン銅鋼石 | 0x070A | 10 |
| 29,500 | 캐라반 은강석 / キャラバン銀鋼石 | 0x070B | 10 |
| 99,000 | 마하광석 / 摩訶鉱石 | 0x2337 | 10 |
| 100,500 | 백은결정 / 白銀結晶 | 0x2338 | 5 |
| 102,000 | 황금결정 / 黄金結晶 | 0x2339 | 5 |

ID는 원문 각 아이템의 Ferias 링크에서도 대조했다. 같은 임계점의 같은
아이템이 원본에서 여러 행으로 나뉘었을 가능성은 남지만, 이번 표는 그 단계
총수량을 한 행으로 지급한다. 점수 구간 사이에 임의 분배하지 않는다.

**GR 적용 범위는 추론**이다. 세 글에는 HR/GR 탭 표기가 없으며, G급 소재를
포함한 전체 표 구성과 비상자 20,000점/5개가 별도 2017년 GR 화면과 일치하는
점을 근거로 기존 GR 역사 보완표에 한정했다. HR까지 확대하지 않는다. 해당
과거 표의 단일 점수·수량은 직접 기록이지만, 40회에도 같았다고 주장하지 않는다.
`historical-2016-single-threshold-gr-inferred`로 출처를 구분한다.

기존 20,000점 6행과 영수증 키는 그대로 보존한다. 추가 5행도 해당 회차의
기도 점수로 판정하여 임계점별 한 번만 발급하며, 저장 성공과 함께 수령을 확정한다.
34,500~39,500점 금강석 10개, 87,000~99,000점 비보 15개, GP 합계와
회차별 기주 무기 소재는 추가하지 않는다. 일회 지급을 무한 반복으로 바꾸지 않는다.

기도 개인 달성의 마지막 페이지 구성과 실제 반복 지급 조건은 이번 블로그
대조만으로 확정되지 않았다. [기존 클라이언트 분석 기록](diva-historical-prayer-rewards.md)의
표시 규칙과 역사 자료의 지급 규칙은 별도로 검증해야 한다.
추가 MCP 분석 결과는 [로테이션 형식 분석](diva-norma-rotation-analysis.md)에 기록했다.

## 검증

`go test -race ./server/channelserver ./server/migrations -run '^TestDiva' -count=1 -timeout=120s`
통과. 새 임계점 전후, GR 제한, 총 23행/GR 11행, 키 고유성, 고득점에서도
일회 보수만 유지하는 테스트를 포함한다. 영수증 보존 DB 통합 테스트는 별도
테스트 PostgreSQL(localhost:5433) 미가동으로 SKIP했으며 운영 DB를 대신 쓰지 않았다.
gofmt와 `git diff --check`도 통과했다. 배포·서버 재시작·커밋은 하지 않았다.
