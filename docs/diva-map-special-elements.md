# 요격전 지도 특수 보물: 원본 규칙과 서버 표시 지원

> 최신 운영: [지도 v3 운영 규칙](diva-map-progressive-operation.md)에는 승인된
> 단계별 붉은 보물 확률과 침공이 추가되어 있습니다. 아래의 기본 비활성,
> `off/random-one/all`, v2 전용 선택 설명은 기존 v1/v2 운영 범위입니다.
> v3는 별도의 고정 확률을 사용하며, 기존 회차·보수량을 소급 변경하지 않습니다.

조사일: 2026-09-23. 대상: `mhfo-hd.dll.clean.mapped.bin`.
이 문서는 원본 규칙, 역분석으로 확인한 wire 동작, 서버 운영상 선택을 구분합니다.
기존 `custom-v1`/`custom-random-v2` 생성 정의와 보수표는 변경하지 않습니다.

## 공식 자료에서 확인한 범위

[서비스 종료 직전 공식 매뉴얼 page399](https://web.archive.org/web/20191218054658id_/http://cog-members.mhf-z.jp/sp/manual/page399.html)의 「戦況マップ → お宝」에 근거합니다.
웹 도구에서는 접근 오류가 있었지만 동일 URL을 HTTP로 읽어 원문을 확인했습니다.

- 보물 에리어를 획득하면 보물이 해금되며, 보수 확인·수령 메뉴에서 받습니다.
- 보물은 노란색과 붉은색 두 종류입니다. 붉은 보물은 에리어를 획득하기 전에는 내용이 표시되지 않습니다.
- 에리어 획득 후 보물 아이콘이 바뀝니다. 이는 개인이 보수를 수령했는지와 다른 상태입니다.
- 분기에서 획득한 에리어도 수렵단 달성 보수에 계산됩니다.
- 다음 지도에 진입한 뒤 이전 지도 분기는 더 진행할 수 없습니다.
- 보물은 다음 요격전 개최 전까지 수령할 수 있습니다.

원본 이미지 경로는 같은 호스트의 `/sp/manual/image/399_48.jpg`(두 종류),
`399_49.jpg`(획득 후 아이콘), `399_51.jpg`(분기 상세)입니다.
공식 설명에는 붉은 보물의 출현 확률·지도별 배치 수·가치 차이·품목 수량표가 없습니다.
따라서 붉은색이라는 이유로 더 비싼 보수를 배정하거나 새 확률을 원본이라고 만들지 않습니다.
개인별 분기 기여 조건은 이전에 승인한 서버 운영 정책이며 이 짧은 공식 설명만으로
원본의 모든 개인 수령 자격이 동일하다고 단정하지 않습니다.

## 네이티브 필드와 상태 전이

| 요소 | 원본 소비 경로 | 확인한 동작 |
|---|---|---|
| 정의 wire `+18`, `TreasureMode` | `103b9440` → 화면 노드 `+0x24` → `103a90b0` case 6 | 0이면 보물명 조회, nonzero면 보물명 인덱스를 모두 -1로 처리 |
| 미공개 상세 문구 | `103a7750` | 두 보물 포인터가 모두 NULL이면 기존 리소스 표 `+0xfb0`, 항목 `+0x18` 문구 사용 |
| 보물행 wire `+13`, `DisplayMode` | `103b96e0` | `<=1`은 아이콘 상태 1/3, `>1`은 2/4. 뒤 번호는 에리어 획득 상태 |
| 획득 판정 | 화면 노드 `+0x10` | `max(required-earned, 0) == 0`이면 획득한 아이콘 |
| 실제 표시 슬롯 | `103a4db0` | 보물 상태 1→5, 2→7, 3→6, 4→8 아이콘 선택 |
| 보물행 지도 범위 | `103b8ce0`, `103b8d90` | 그룹 ID가 같고 MinMap ≤ 현재 지도 번호 ≤ MaxMap인 행 조회 |

일반/붉은 보물이라는 명칭과 1/2 아이콘군 대응은 **공식의 두 종류 설명과 두 가지
네이티브 아이콘군을 대조한 추론**입니다. 이 조사에서 실제 텍스처 픽셀의 색을 확인하거나
실행 중 클라이언트에 값을 주입하지는 않았습니다. 인게임 표시 확인이 남아 있습니다.

중요하게도 `TreasureMode`는 클라이언트가 획득 상태에 따라 자동으로 해제하지 않습니다.
`103b9440`이 무조건 복사하고 `103a90b0`이 그대로 검사합니다. 따라서 서버 응답은 다음과
같이 전환해야 합니다. 보수 수령 여부가 아니라 정산된 에리어 점수를 기준으로 합니다.

| 선택한 보물 상태 | TreasureMode | DisplayMode | 네이티브 아이콘 상태 |
|---|---:|---:|---:|
| 일반·미획득 | 0 | 1 | 1 |
| 일반·획득 | 0 | 1 | 3 |
| 붉은 표시·미획득 | 1 | 2 | 2 |
| 붉은 표시·획득 | 0 | 2 | 4 |

이것은 **화면상 미공개**입니다. 보수 행 자체는 응답에 남으므로 패킷 분석까지 막는
암호학적 은닉이 아닙니다. 빈 보수 행으로 보물을 숨기면 아이콘까지 사라질 수 있어
그 방식으로 구현하지 않습니다. 이전 지도 페이지는 원본 UI 자체가 상세 보물명을 숨깁니다.

## 구현 경계

`diva_map_special_treasures.go`의 `DivaMapSpecialTreasureSelection`은 명시적인
`MapNumber + GroupID` 선택입니다. `projectDivaMapSpecialTreasures`와
`divaMapSpecialTreasurePayload`는 기존 지도 데이터를 깊은 복사한 뒤 전송 표시만 바꿉니다.

- 무선택은 기존 wire와 완전히 동일하며 v1/v2 모두 지원합니다.
- 선택 적용은 엄격히 검증된 v2 지도만 지원합니다. v1은 현재·직전 페이지가 단일 정의를
  공유하므로 새 표시 정책을 소급 적용하지 않습니다.
- v2의 현재·직전 지도에 선택이 서로 달라도 올바르게 표시하도록 보물행 지도 범위를
  실제 각 지도 번호로 나눕니다. 선택하지 않은 지도나 그룹의 색은 그대로입니다.
- 에리어 미획득 시 숨기고 획득 시 공개하지만, 원본 저장 정의·점수·획득 에리어 수·
  메인/분기 퀘스트·길드 티켓 5개 + GP 500 보수·기여/수령 원장은 바꾸지 않습니다.
- 반환된 투영 객체는 **전송 전용**입니다. canonical v2 검증을 통과하지 않으므로
  저장 지도나 보수 카탈로그로 재사용하면 안 됩니다.
- 음수/0/존재하지 않는 지도나 그룹, 중복 선택, 변조한 보수표는 거절합니다.
- wire validator는 확인한 `TreasureMode=0/1`, `DisplayMode=0/1/2`만 허용하며
  보물 없는 노드의 숨김 플래그는 거절합니다. 기존 v2 canonical 검증은 여전히
  원래 mode 0/1 조합만 허용합니다.

이 순수 계층은 붉은 보물 배치 수나 확률을 정하지 않습니다. 아래 명시적인 회차별
운영 정책을 별도로 연결했습니다. 기본값은 비활성이며 운영 DB/config.json은 변경하지 않았습니다.

## 명시적 운영 선택과 회차 경계

`GameplayOptions.DivaMapRedTreasureMode`의 기본값은 `off`입니다.

| 값 | 신규 v2 회차의 표시 정책 |
|---|---|
| `off` | 종전과 동일. 숨김/붉은 표시를 추가하지 않음 |
| `random-one` | 지도마다 기존 보물 둘 중 하나만 선택 |
| `all` | 기존 보물 둘 모두 선택 |

이는 원본 분포를 복원한 값이 아니라 명시적으로 선택할 **서버 운영 정책**입니다.
활성 값은 ZZ와 정상 이벤트 시각에서만 허용합니다. 선택은 회차 seed + 지도 번호의
독립 PRNG 영역으로 결정하므로 재접속·재시작·다른 수렵단·직전 페이지 전환으로 다시
추첨하지 않습니다. 경로 생성 PRNG와 원본 v2 정의에는 영향을 주지 않습니다.

0061은 현재 정책과 변경 이력을 저장하고, 기존 `diva_map_events`에는 `off` 기본값만
추가합니다. 기존 회차는 이를 변경할 수 없도록 trigger로 보호합니다. 설정을 동일하게
유지한 재시작은 적용 시각이나 이력을 늘리지 않습니다. 설정 변경 뒤에 실제로 시작하는
신규 회차부터 그 시점의 정책을 고정합니다. 회차 시작 후 첫 지도 조회 전에 설정을
바꾼 경우에도 변경 이력에서 시작 당시 정책을 찾아 사용합니다.

설정 초기화 실패는 경고 후 해당 프로세스의 특수 표시만 비활성화합니다. 선택적 정책
조회 SQL은 savepoint로 분리하여 PostgreSQL 오류가 전체 지도 트랜잭션을 중단시키지
않게 합니다. 신규 회차 정책을 읽을 수 없으면 `off`로 고정하며, 기존 표시 조회 실패나
표시용 선택 오류도 일반 지도 응답으로 돌아갑니다. 핵심 지도 데이터 자체가 잘못된
경우에는 종전의 종료 오류 응답을 사용합니다.

설정 변경/마이그레이션은 map JSON, 출발/기여/에리어 원장, 보수 receipt를 수정하지
않습니다. handler만 조회 결과에 붙은 명시 선택으로 표시용 payload를 생성합니다.
지급 자격·수량·보수 검증은 계속 저장된 canonical 지도와 기존 원장을 사용합니다.

## 미확보 요소와 검증

후속 [원본 타일 분석](diva-map-native-tile-rules.md)에서 격전지·우세/열세 표시가
기본/현재 필요 점수 차이와 획득 여부로 결정됨을 확인했습니다. 침공 수식·발생 주기는 미확보입니다.

원본 지도에서 보물 수·분기 길이·색 분포·보수표를 정하는 규칙은 아직 미확보입니다.
정의 `Unknown02/04/06/08/10/12`, 상태 `Unknown21/22`에 숨김 에리어 등의 새 의미를
임의로 부여하지 않았습니다. 지금 확인한 숨김은 보물의 **내용 표시**이며 지도 타일
자체를 숨기는 기능이라고 주장하지 않습니다.

순수 회귀 테스트는 무선택 wire 동일성, 부분 점수/정확 임계점의 공개 전환, 실제 wire
offset, 현재·직전 지도별 색 분리, 보수/점수 불변, 입력과의 alias 방지, 잘못된 선택과
보수 변조 거절, 1,000-seed 정책 재현을 검사합니다. 기존 생성기/프로토콜 테스트도
함께 통과했습니다. 별도 DB 테스트는 회차 정책 불변, 미조회 회차의 정책 이력,
재시작 보존, SQL 오류 savepoint 복구, migration 재실행과 기록 불변을 검사합니다.
실게임 색상·문구·보수 수령 화면 검증을 대체하지는 않습니다.
