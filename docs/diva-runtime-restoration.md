# 가희 안내·랭킹·미수령 보수 후속 보완

2026-09-21. 사용자 요청에 따라 **첫날 집계는 18:00을 유지**한다.
공식 자료의 18:30과 다른 의도적인 운영 규칙이며, 일반 집계는 04:00/12:00/20:00이다.
자정 시작 회차도 첫날은 18:00 이전에 공개하지 않는다. 첫날 18:00/20:00 이후
다음 날부터 일반 집계 시각을 적용한다.
검증한 항목과 기존 70% 이상으로 판단한 과거 회차 추론만 사용한다.
이는 확률 측정치가 아니며 미확보 보수의 임의 생성은 승인되지 않았다.

## 실제 안내

ZZ `MSG_MHF_GET_UD_INFO`를 이용해 기존 가희 NPC의 안내 화면에 다음을 보낸다.

- 기도의 장: GR 매일 보수, 개인 랭킹 수령 시기, 설정된 타깃 보너스, 이전 요격 보수의 기한.
- 전가의 장: 새 회차의 GR 요격 개인 달성 보수와 다음 요격전 시작 전까지의 수령 기한.
- 가영의 장/개최 사이: 미수령 요격 보수의 수령 기한.
- 아직 제공할 수 없는 기도 개인 달성·수렵단 랭킹 보수, 지도·에리어·보물·선율 교환·특별 수렵단방을 명시한다.

원본 40회 모든 기능을 복원했다는 문구를 사용하지 않는다. 기존 57행 중 수령에 연결된
45행과, 지도 자격이 없어 목록만 제공하는 수렵단 12행의 구분은 그대로다.
새로운 미검증 보상이나 다른 회차의 전체 표를 임의로 넣지 않는다.

### 안내 패킷 근거

분석 프로그램: `mhfo-hd.dll.clean.mapped.bin`.

- `114fd150`: opcode 0x15c, 수신 payload 최대 0x1021바이트.
- `11534450`: u8 count + count × {CP949 패치 클라이언트 text[1024], start u32, end u32}.
- `103b80a0`: 고정 네 슬롯을 스캔해 현재 시간이 시작/종료 사이(양끝 포함)인 첫 행을 선택.
- `103b3730`: 해당 행의 텍스트를 기존 안내 레이아웃에 표시.

파서가 이전 슬롯을 지우지 않으므로 항상 네 행을 보내고 미사용 행을 0으로 비운다.
기간은 서로 겹치지 않도록 종료 시각을 다음 구간 시작 -1초로 보낸다.
비활성화 시에도 네 슬롯을 지운다. 검증하지 않은 다른 버전에는 기존 빈 응답을 유지한다.
기도 고정 모드에서는 종료 후 개인 랭킹 보수를 받을 수 있다고 오안내하지 않는다.
안내창 440×348px/좌측 여백 40px/글자 크기 18px에 맞춰, 각 줄은 360px 이하
(ASCII 최대 12px, 전각 18px), 전체 열 줄 이하로 제한한다.
한국어·영어와 모든 옵션 조합을 테스트한다.

## 보너스와 미복원 데이터의 경계

`DivaBonusRandom=true`일 때에만 3시간 간격, 4색, 몬스터 중복 최소화, 조건 일치 시 2배라는
기존 운영 규칙을 안내한다. 기본값은 여전히 false이며 운영 config.json은 이 작업에 없다.
수동 대상 목록은 대상·시간 확인 안내를, 둘 다 없으면 미설정 안내를 보낸다.
서버가 이미 클라이언트에서 계산한 점수에 다시 배율을 적용하지 않는다.

선율 교환은 상품 수량, 획득 단계 전체, 특별 수렵단방 해금 및 저장 정합성 연결이 남아 있다.
GET/USE 응답을 검증했어도 재화 지급·상품 교환을 활성화했다고 보지 않는다.
자세한 내용은 [선율 조사 기록](diva-melody-exchange.md)을 참고한다.

## 랭킹

기도 개인/수렵단 순위와 내 순위를 실제 노래 구슬 원장으로 계산한다. 수렵단은 적립 당시
소속의 합계이며 이적 후 과거 실적을 새 수렵단으로 옮기지 않는다. 기존 원장은 과거 소속을
알 수 없어 수렵단에 소급 배정하지 않는다. 개인 실적 자체는 그대로 보존한다.
동점은 기존 경쟁 순위(1,1,3)를 유지하며, 원본의 동점 세칙까지 확인했다는 뜻은 아니다.

ZZ 실제 기도 UI는 kind 0 개인/2 수렵단을 요청하며 둘 다 31바이트 행이다.
상위 100명/수렵단과 별도로 자신의 순위·점수도 전달한다. 0점 수렵단은 내 정보에만
표시하고 상위 목록에는 넣지 않는다. 미확인 kind 1/3을 과거 순위라고 가정하지 않는다.
요격 랭킹은 실제 에리어 원장이 없어 임시 이름·점수를 제거하고 정확한 크기의 빈 목록을 보낸다.

원본 근거: [공식 최종 매뉴얼](https://web.archive.org/web/20191218054658id_/http://cog-members.mhf-z.jp/sp/manual/page399.html),
[40회 실제 개인·수렵단 랭킹 기록](https://kakeru.kakuren-bo.com/memory/utatama).
매뉴얼은 요격 에리어 순위의 04/12/20시 갱신과 다음 요격전 개최 전까지의 보수 수령을 명시한다.

## 적용과 검증

코드와 마이그레이션 반영이며 운영 DB 직접 변경·배포·커밋은 하지 않는다.
업데이트 서버 시작 때 마이그레이션이 적용된다. 수렵단 귀속이 없는 과거 개인 기록은
보존하지만 현재 소속으로 소급 합산하지 않는다.
클라이언트가 안내·보너스 목록을 캐시하므로 배포 후 재접속해서 확인해야 한다.
원본 UI에서 실제 문구 줄바꿈·수령·재접속 확인은 별도 인게임 검증이 필요하다.

이번 변경 검증: 전체 `go build ./...`, 변경 패키지 `go vet`, config/packet 전체 `-race`,
channelserver의 Diva/Ud/Tactics/QuestRun/Stage/WeaponDeparture 관련 `-race`, 격리 DB의
`server/migrations` Diva 마이그레이션 테스트를 통과했다. 전체 저장소 테스트 통과를 의미하지 않는다.
기도 기간의 요격 개인 보수 상위 메뉴 진입은 native 정적 분석으로 확인했다.
