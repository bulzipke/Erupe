# 요격전 지도 v3: 승인된 서버 커스텀 운영 규칙

2026-09-23. `custom-progressive-v3`는 사용자가 승인한 서버 전용 난도·확률표입니다.
**40회 원본 지도, 원본 침공 주기 또는 원본 보물 출현 확률을 복원한 것이 아닙니다.**
클라이언트가 지원하는 기존 격전지·강화 거점·보물 숨김 표시에 서버 운영 규칙을 연결합니다.
표시 필드의 역분석 근거는 [원본 타일 표시 규칙](diva-map-native-tile-rules.md),
보물 표시의 의미와 한계는 [특수 보물 표시](diva-map-special-elements.md)에 있습니다.

## 적용 범위와 기존 기록 보존

- 마이그레이션 `0062`가 최초 실행된 시각을 영구 경계로 저장합니다. **그 시각 이후에 실제로
  시작하는 새 요격 회차**만 v3 대상입니다. 마이그레이션을 다시 실행해도 경계는 바뀌지 않습니다.
- 이미 저장된 `custom-v1`/`custom-random-v2` 회차는 버전·seed·지도·필요점수·획득영역·
  출발/기여 원장·보수 영수증을 그대로 유지합니다. 진행 회차에 v3를 소급 적용하지 않습니다.
- 현재 회차에서 지도를 아직 한 번도 조회하지 않았더라도 실제 회차 시작이 경계 이전이면
  v3로 바뀌지 않습니다. 늦은 활성화 시각이나 첫 조회 시각으로 회차 시작을 대체하지 않습니다.
- 이미 `DivaOverride`로 고정 운영 중인 회차도 그대로입니다. 재시작, 지도 재조회 또는
  override 유지가 기존 회차를 v3로 변환하는 수단은 아닙니다.
- v3의 붉은 보물 선택은 아래 확률을 자동으로 사용합니다. 기존
  `DivaMapRedTreasureMode=off/random-one/all`은 v2 운영용으로 유지하며 v3에 덮어쓰지 않습니다.

HR 선율 조건을 GR 조건의 절반으로 적용하는 별도 승인 사항은
[HR 선율 커스텀 조건](diva-hr-melody-restoration.md)에 정리되어 있습니다.
이는 지도 난도·영역 보수 변경이 아니며, 계정 내 여러 캐릭터의 선율을 합산하는 기능도 아닙니다.

## 지도 번호별 운영표

단계는 `min((지도번호 - 1) / 2, 4)`이며 정수 나눗셈을 사용합니다.

| 지도 번호 | 시간 침공 추첨 간격 | 각 대상 칸의 초기·시간 침공 확률 | 성공 1회당 추가 비율 | 각 보물 분기의 붉은 표시 확률 |
| --- | ---: | ---: | ---: | ---: |
| 1~2 | 정각 갱신 6회마다 | 5% | 기본 필요점수의 +5% | 10% |
| 3~4 | 정각 갱신 5회마다 | 10% | 기본 필요점수의 +8% | 20% |
| 5~6 | 정각 갱신 4회마다 | 20% | 기본 필요점수의 +12% | 35% |
| 7~8 | 정각 갱신 3회마다 | 30% | 기본 필요점수의 +16% | 50% |
| 9 이상 | 정각 갱신 2회마다 | 40% | 기본 필요점수의 +20% | 65% |

지도가 생성될 때 메인 경로의 각 대상 칸에 초기 추첨을 한 번 적용합니다. 이후 표의 갱신
횟수에 도달할 때마다 아직 획득하지 않은 메인 칸을 각각 독립적으로 추첨합니다.
시작 지점과 보물 분기는 침공 대상이 아니며, 메인 경로의 목표 거점은 포함됩니다.
한 번의 시간 침공에서 여러 칸이 동시에 강화되거나 아무 칸도 강화되지 않을 수 있습니다.

기본 필요점수는 **현재 지도 번호의 정상 난도를 이미 반영한 값**입니다. 기존 페이지 난도는
1번 1배, 2번 1.25배, 3번 1.5배, 4번 1.75배, 5번 이상 2배로 유지하며, 이 값 자체를
침공 추가분으로 표시하지 않습니다. 보물 분기의 정상 필요점수도 유지합니다.

## 필요점수와 획득 상태

침공 비율은 복리로 곱하지 않고 기본점수에 대한 추가 비율을 누적합니다.
추가 비율의 상한은 100%이며, 최종 필요점수는 다음과 같습니다.

`ceil(현재 지도의 기본 필요점수 × (100 + 누적 추가 비율) / 100)`

따라서 **침공으로 증가한 필요점수는 해당 지도 기본점수의 최대 2배**입니다. 이는 언제나
첫 지도의 2배라는 뜻이 아닙니다. 나눗셈의 소수점은 최종 계산에서 한 번 올림합니다.

- 이미 획득한 칸은 필요점수와 강화 비율을 동결합니다. 다시 빼앗거나 미획득으로 돌리지 않습니다.
- 진행 중인 칸에 이미 적립한 점수는 그대로 보존합니다. 침공은 남은 필요량을 늘릴 뿐,
  개인 요격 점수나 수렵단이 제출한 기여 점수를 차감하지 않습니다.
- 누적 획득영역·수렵단 보수 자격·발급된 보수 영수증은 침공 때문에 되돌리지 않습니다.
- 시작점과 분기 구조, 퀘스트 배정, 지도 끝의 초과점수 폐기 규칙은 그대로 유지합니다.

## 시간 경계·재접속·재시작

정산 순서는 **직전 정각 이후의 유효 기여 반영 → 획득 판정과 지도 전환 → 시간 침공**입니다.
방금 획득한 칸은 같은 정산의 침공 대상에서 빠집니다. 정각과 정확히 같은 시각에 제출된
기여는 기존 규칙대로 다음 정산 구간에 포함됩니다.

- 수렵단의 첫 지도 생성 이전 시간에는 침공을 소급 적용하지 않습니다. 회차가 시작된 뒤
  며칠이 지나 처음 지도를 열었다고 지난 며칠의 강화가 즉시 쌓이는 방식이 아닙니다.
- 첫 생성 이후에는 기여가 없는 정각도 갱신 횟수에 포함합니다. 접속자가 없거나 서버가
  잠시 정지했다면 이후 정산에서 저장된 시점 다음부터 순서대로 따라잡습니다.
- 주기는 실제 정각 갱신 횟수 기준입니다. 생성 후 정확히 6×60분을 기다리는 별도 타이머가
  아니므로, 예를 들어 14:50에 생성된 1번 지도의 6번째 갱신은 20:00입니다.
- 다음 지도로 넘어가면 새 페이지의 갱신 횟수는 0입니다. 새 페이지 생성 시 초기 추첨은
  적용하지만, 넘어온 그 정산 구간의 시간 침공까지 중복 적용하지 않습니다.
- 이전 페이지의 진행·강화 비율·갱신 횟수는 보존합니다. 요격 회차 종료 경계에는 새 시간
  침공을 만들지 않으며, 종료 후 미수령 보수 확인 때문에 필요점수가 더 증가하지 않습니다.
- 회차 seed·지도 번호·좌표·갱신 횟수로 추첨을 재현하고 결과를 저장합니다. 지도 재조회,
  재접속, 재시작은 새 추첨 기회가 아닙니다. 같은 정각 처리의 재시도도 중복 증가하지 않습니다.

실제 필요점수가 증가한 정각에는 기존 클라이언트 전황 로그의 kind 3 문구를 한 번 기록합니다.
모든 추첨이 실패했거나 이미 상한인 칸만 남아 변화가 없으면 증가 로그를 만들지 않습니다.
클라이언트의 미확인 필드에 별도 침공 확률·시간 값을 억지로 넣지 않습니다.

## 보물 표시와 보수

기존 두 분기 각각에 위 표의 붉은 표시 확률을 적용합니다. 지도·분기별 선택은 고정되어
보물 둘 모두 일반이거나, 하나만 붉거나, 둘 모두 붉을 수 있습니다. 붉은 표시에는 에리어를
획득하기 전 내용 숨김을 적용하고, 획득 후에는 내용을 공개합니다. 개인 수령 여부와는 다릅니다.

**보물 보수는 기존 수렵단 티켓 5개 + GP 500으로 유지합니다.** 붉은색이라는 이유로
품목·수량·확률형 지급·별도 보상을 추가하지 않습니다. 기존 분기 기여 및 수령 자격과
현재/직전 지도별 표시 분리도 유지합니다. 화면에서 숨겨도 보수 행 자체는 패킷에 남으므로
패킷 분석까지 막는 암호학적 은닉은 아닙니다.

## 검증 범위

`diva_progressive_map_test.go`의 순수 race 테스트는 단계별 표, 8,000개 seed의 확률 분포,
강화 상한, 획득 칸 동결, 부분점수 보존, 정각 순서·재시도, 페이지 전환, JSON 보존,
변조 거절, 레거시 분리 및 보물 숨김/공개 시 보수 불변을 검사합니다. 이는 계산·직렬화
검증이며 **실제 인게임에서 표시·로그·보수 수령까지 성공했다는 의미는 아닙니다.**

DB 통합 테스트와 마이그레이션 검증 결과는 해당 실행 기록을 따릅니다. 운영 반영 후에는
새 v3 회차 여부, 정각 전후 점수와 격전지 표시, 이전 페이지, 전황 로그, 숨겨진 보물의
획득 후 공개, 기존 보수 수령을 실제 클라이언트에서 따로 확인해야 합니다.
