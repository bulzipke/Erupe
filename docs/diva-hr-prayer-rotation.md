# HR 기도 개인 달성 반복 보수 — 추론 운영표

2026-09-22. 사용자가 지금까지의 자료로 HR 보수도 유추하여 구현하도록 요청했다.
**40회 원본 HR 반복표를 복원한 것은 아니다.** 기존 HR 일회 보수와 GR 운영표는
유지하고, 기도 개인 달성 보수에 아래 반복 구간만 추가한다. 요격전 표는 변경하지 않는다.

## 적용 표

| 점수 | HR2–4 | HR5–7 |
| ---: | --- | --- |
| 100–20,000 | 기존 6단계 일회 보수 유지 | 기존 6단계 일회 보수 유지 |
| 21,000 | 기도의 조약돌 1개 | 기도의 조약돌 2개 |
| 22,000 | 길드 공헌 포인트 100 | 길드 공헌 포인트 200 |
| 23,000 | 기도의 조약돌 1개 | 기도의 조약돌 2개 |
| 이후 매 1,000점 | 조약돌 → GP 순서로 반복 | 조약돌 → GP 순서로 반복 |

시작점은 포함한다. GR은 기존 103,000점 시작·1,000점 간격·백은결정/황금결정
각 5개 순환을 유지한다. 실제 저장 HR 경계는 2–99 / 100–999이며 GR>0이면
HR 표를 적용하지 않는다. HR0/1/1000 이상·음수 점수에는 새 HR 자격이 없다.

품목·수량은 `server/channelserver/diva_hr_prayer_rotation.go`에 명시하며, 새
설정 옵션은 추가하지 않는다. `custom-inferred-hr-prayer-2026-09-22`로 출처를
구분한다. 현재 회차의 서버 노래 구슬 기록만 사용하고 과거 회차 누적치에는 소급하지 않는다.

## 추론 근거와 한계

- [2017-05-24 실제 플레이 기록](https://mhf-akia.blog.jp/archives/1066139125.html)은
  기도의 장 GP 획득과 기도의 조약돌을 무기 소재로 교환하는 용도를 설명한다.
- [35회 기록](https://byuwasoku.hatenablog.com/entry/2019/08/08/120640)은 조약돌의
  무기 생산 소재 교환 대상 확대를 설명한다. 두 글 모두 HR 반복 주기·수량의
  직접 근거는 아니다.
- 조약돌 1/2개, GP 100/200은 이미 승인된 HR 단계표의 품목·하위/상위 배율과
  최저 GP 단계량을 따른 운영 추론이다. 21,000점은 기존 최종 20,000점 다음,
  간격 1,000점은 현재 GR 운영안에 맞춘 값이다. 원본 확인값으로 주장하지 않는다.
- 추가 10,000점당 조약돌 5/10개와 GP 500/1,000을 얻는다. 원본 밸런스와
  같다는 보장은 없다. 기존 혼옥 일회 보수는 유지하며, 신규 반복에 GR 전용 소재나
  미확인 과금 아이템을 복제하지 않는다.

## 표시 방식

실제 Go 응답 29행의 품목·수량·플래그를 클라이언트 함수에 격리 입력하여 검증했다. 두 HR 탭은 기존
6행을 일반 1/2페이지, 21,000/22,000점 두 행을 반복 2/2페이지로 나눈다.
GR 3페이지 구성은 유지한다. 클라이언트/Vorbis 파일이나 실행 중 메모리는 수정하지 않는다.

서버는 점수순 stable 정렬로 보내고, 동점에서는 HR2–4를 HR5–7보다 먼저 둔다.
원본 함수의 이전 행 검색은 HR 상하한을 구별하지 않으므로, HR2–4의 첫 반복
행만 표시 플래그 0, 나머지 HR 반복 행은 1로 보내야 한다. 네 행 모두 1이면
HR5–7의 기존 20,000점 보수가 반복 페이지로 섞인다. 이것은 표시 전용 예외이며
그 첫 행도 실제 반복 지급이다. 표시용 행은 기존 일회 자격 목록에 넣지 않는다.

## 승급·저장 보호

- HR2–4와 HR5–7은 회차·캐릭터별 **하나의 HR 처리 순번**을 공유한다.
  발급된 낮은 등급의 보수는 승급 후에도 유지하고 같은 순번을 다시 발급하지 않는다.
  아직 발급하지 않은 다음 순번부터 새 등급 수량을 적용한다.
- GR 순번은 별도로 보존하되 `milestone-<점수>` 공통 기록을 사용한다.
  예를 들어 HR에서 103,000점 보수가 발급됐다면 GR 승급 후 그 점수의
  백은결정을 추가 발급하지 않는다. 이미 선택한 미수령 보수도 그대로 받을 수 있다.
- HR 반복 99,000/102,000점처럼 기존 GR 일회 보수와 겹치는 점수도 같은 원칙이다.
  한 점수의 최초 선택 등급을 유지한다. 원본 승급 규칙 복원이 아닌 중복 방지 정책이다.
- `0052`는 GR 진행도와 기존 지급/미수령 영수증을 보존하고, 기존 GR 반복
  기록의 실제 기준점을 공통 중복 방지 그룹에 보충한다. 데이터를 초기화하지 않는다.
- 반대 등급에서 이미 처리한 연속 점수 구간은 한 번에 건너뛰되, 그 구간보다
  낮은 미지급 HR 점수는 없애지 않는다. 중복 건너뛰기로 빈 응답을 먼저 보내
  뒤의 실제 미수령을 숨기지 않도록 한다.
- 한 응답은 기존 보수 포함 최대 32건이다. 소재와 GP 저장 성공 시 각각 수령을
  확정하며, 실패·재접속·동시 요청에 대해 발급/진행도를 같은 트랜잭션으로 처리한다.
- 두 HR 등급의 정책을 함께 지문화하여 정상적인 승급은 허용하면서 회차 도중
  수량·주기 임의 변경으로 같은 보수를 재지급하는 것은 거절한다.

## 검증 결과

- `go build ./...` 통과.
- 격리 PostgreSQL에서 `go test -race ./server/channelserver -run '^Test(Diva|RepoDiva)'`
  통과(79.508초). 신규 HR 및 기존 GR 통합 검사는 SKIP 없이 실행했다.
- 시작점/등급 경계, 기존 GR 지문 보존, 하위→상위 HR 미수령 묶음 보존,
  HR→GR의 33개 겹치는 점수 건너뛰기, GR→HR의 앞 점수 보존,
  정책 변경 실패 시 일회 보수까지 롤백하는 것을 확인했다.
- 별도 테스트 DB에서 신규/기존 Diva 마이그레이션과 빈 DB 전체 설치,
  정상 재실행 검사 모두 `-race` 통과(7.469초). 0052는 기존 GR 순번·지문·
  영수증·수령 시각을 보존하며 비정상 키 정수 변환과 중복 그룹을 방어한다.
- 원본 함수에서는 실제 소재/GP 행까지 포함해 HR 두 탭의 6행 일반/2행 반복
  페이지 및 기존 GR 3페이지가 유지됨을 확인했다. 이는 인게임 화면 렌더링
  자체가 아닌 격리된 원본 페이지 처리 함수의 실행 검사다.

배포·운영 DB 수정·커밋은 하지 않았다. 실제 게임 화면과 수령의 최종 확인은 별도다.
