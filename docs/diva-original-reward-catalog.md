# 가희수위전 원본 보수: 회차별 확인 목록

조사일: 2026-09-21. **복원 기준은 사용자가 선택한 진설 40회다. 후속 구현에서 직접 확인 41행과 추론 16행을 부분 반영했다.**
현재 적용 범위·수령 가능 여부는 [후속 적용표](diva-round40-applied.md)를 우선한다.
아래 조사 당시의 '미적용/미구현' 문구는 그 시점의 기록이며, 전체 원본 복원 완료를 뜻하지 않는다.
전 회차의 완전한 복원본이 아니다. 사용자 요청에 따라 미확보 항목은 과거 회차로
추론 복원을 시도하되, **40회 직접 확인 / 과거 회차 기반 추론 / 미확보**를 구분한다.
추론 행을 40회 원본으로 확정하거나 누적 합계를 개별 지급량으로 변환하지 않는다.
구 「歌姫狩衛戦」 1회와 리뉴얼 「歌姫狩衛戦・真説」 1회는 별개다.

## 선택한 기준: 진설 40회 (마지막 개최)

캡콤의 2019-11-27 공식 공지가 **40회를 마지막 개최**로 명시한다.
기도의 장 기간은 2019-11-27 점검 종료~2019-12-04 점검 시작이다.
[Capcom 공식 발표](https://prtimes.jp/main/html/rd/p/000001203.000013450.html).
같은 공지의 소재 획득 10배·소판 G 999개는 **제147회 수렵제** 혜택이다.
이를 40회 가희수위전 보수로 추가하지 않는다. 마지막이라는 이유만으로
매일/개인 달성 보수가 모든 이전 회차보다 많다고 단정하지 않는다.

40회 당시 기록에서 확인한 변경점:

- 기가 사용 가능 횟수 20→25회. 현재 스케줄의 0x19와 수치는 같지만,
  스케줄 값만으로 실제 사용 횟수의 저장·차감이 구현됐다고 볼 수 없다.
- MHF 오리지널 몬스터의 노래 구슬/요격 포인트 우대.
- **기도의 장 개인 랭킹 보수(전가의 장에서 수령)**의 혼옥류를
  `迎撃の橙団旗`로 변경. 30/20/10개인 실제 표를 아래에서 확인했다.
  전가의 장 요격전의 에리어 랭킹과 혼동하지 않는다. 별도 요격전 랭킹 보수는 존재 미확인이다.
- 노래 구슬 1점 개인 달성에 `シエルクロワ・アン`(랜스) 생산권.
  생산권은 `Ｃクロワ生産券`(0x2547)까지 확인했다. 수량/랭크 조건은 미확보다.
- 특별 수렵단방 1에리어 해금, `連続迎撃・ばいばい戦`,
  가영의 선율 교환에 `キャリジ生産券Ｄ`·`シャンデ生産券Ｄ` 추가 기록.
  보수 목록과 별개인 퀘스트·방 해금·교환 처리까지 점검해야 한다.

[당시 11월 기록](https://seesaawiki.jp/kokoromemo/d/%A4%B3%A4%B3%A4%ED%A5%ED%A5%B0_2019%C7%AF11%B7%EE),
[마지막 개최 정리](https://seesaawiki.jp/kokoromemo/d/TOPICS%B2%BC%BD%F1%A4%AD%A5%DA%A1%BC%A5%B8),
[연혁의 11/27 항목](https://w.atwiki.jp/giurasu/pages/1526.html).

**매일 보수까지 혼옥을 없애면 안 된다.** 2019-12-03 실제 플레이 기록에는
가희수위전 매일 보수에서 **중혼옥 25개**를 발견한 내용이 있다.
[당시 플레이 기록](https://blog.livedoor.jp/mhfgland/archives/cat_269075.html).
본문은 검색 인덱스에서 확인했으나 원본 페이지가 503을 반환하여
첨부 스크린샷 전체를 읽지 못했다. 따라서 이 기록만으로 HR/GR 조건이나
나머지 참여 일수별 보수를 확정하지 않는다.

#### 가영의 장: 전체 교환품 공식 표 확보

[40회 교환 기사](https://byuwasoku.hatenablog.com/entry/2019/12/02/120036),
[교환 목록 9/10페이지](https://cdn-ak.f.st-hatena.com/images/fotolife/m/machikorokoro/20191128/20191128024438.png)에서
`キャリジ生産券Ｄ`, `シャンデ生産券Ｄ`의 필요 비용은 각각 선율 1개로 보인다.
같은 페이지의 카탄테~프란테 실크와 歌詠ノ布는 각각 음표 2개다.
처음에는 이 음표 UI만 판독했지만, 후속 조사에서
[공식 교환 페이지의 2019-12-15 저장본](https://web.archive.org/web/20191215192228id_/http://members.mhf-z.jp/contents/regular_event/diva/change_item.html)을 복구했다.
공식 HTML의 `歌迎の調べ` 표는 **76행**이며, 66행은 선율 1점, 10행은 2점이다.

| 품목 | 행 수 | 필요 선율 |
| --- | --- | --- |
| ジェス·リアルオ·レウアス·レイレス의 검/사주 GX1~5 | 40 | 각 1 |
| 외장 해방권/생산권 (마지막 キャリジ·シャンデ 포함) | 26 | 각 1 |
| カタンテ·リカンテ·メレンテ·ウタンテ·フランテ 실크, 歌詠ノ布·歌紡ノ布, シャンル·ファンル·ミュンル 실크 | 10 | 각 2 |

원문 표기와 필요 비용은 [조사 전용 JSON](diva40-melody-exchange-evidence.json)에 옮겼다.
이 파일은 서버 설정이 아니며 **서버/DB에 적용하지 않았다**.
공식 표에 별도 지급 개수 열은 없으므로, JSON에 지급 개수나 아이템 ID를 임의로 넣지 않았다.
남성은 パピメル 해방권, 여성은 Ｏビート 해방권을 입수해도 해당 외장을 해방할 수 없다는 주의가 있다.

같은 공식 페이지의 별도 표에는 **노래 스킬 31행, GP 일반 교환 172행,
GP 횟수 제한 교환 131행**도 남아 있다. 스킬/아이템의 해방 레벨, GP 비용,
랭크 제한 및 제한 교환 횟수를 확인할 수 있다. 이들은 선율 76행 및
**수련도(狩煉道) 포인트 교환과 서로 다른 시스템**이므로 한 상점으로 합치지 않는다.

- **기주 변경:** 매뉴얼은 선택한 기주를 기간 중 하루 한 번, 정오 집계가 완료된 뒤
  변경할 수 있다고 설명한다. 클라이언트가 선택 성공을 표시하는 것과 서버의 선택 저장은 별도 확인 대상이다.

  더 이상 HR 보수를 받을 수 없다. HR/GR 표를 동시에 지급하거나 과거 HR 보수를 자동 보상하지 않는다.

  1개 이상을 얻어야 한다. 단순 로그인 일수를 그대로 참여 일수로 계산하지 않는다.

- **요격전 보수 종류:** 최종 매뉴얼은 개인 달성·수렵단 달성·지도 보물을 명시한다.
  에리어 랭킹의 조회·갱신 설명도 있지만 **별도 요격전 랭킹 보수는 명시하지 않는다**.

- **요격전 수령 기한:** 최종 매뉴얼은 다음 요격전 개최 전까지 수령 가능하다고 명시한다.

- **선율은 계정 단위:** 캐릭터별 획득량을 합산하지 않는다. 계정 내 캐릭터 중 가장 많이

  가영의 장 종료 시 선율은 0으로 돌아간다. 아이템 파우치가 가득 차면 교환할 수 없다.
- **복귀 수렵단:** 최종 매뉴얼은 복귀 수렵단 소속 헌터의 요격전 참가를 허용하지 않는다.

그러나 복구한 공식 페이지는 **개인 달성/수렵단 달성의 모든 단계별 보수표를 제공하지 않는다**.
저장소의 예전 Daily/Norma 응답은 동일한 임시 hex 데이터이며
클라이언트가 요구하는 엔트리 수와 길이도 맞지 않아 원본 자료로 사용할 수 없다.

따라서 35회 목록을 40회라고 바꾸어 설치하거나, 초기 회차의 누적 합계를
개별 단계 지급량으로 변환하지 않았다. **40회 전체 보수 구현 완료가 아니다.**
남은 자료는 HR 매일 보수, 기도 개인 달성의 모든 기준점/수량,
기도 수렵단 순위별 표, 요격전 개인 포인트·수렵단 에리어별 표의 누락 페이지와 지도 보물,
보너스 타깃의 색·시간·대상·배율이다.

## 요격전(diva_prizes)·랭킹·보너스 타깃

- 요격전은 개인 **迎撃ポイント**와 수렵단 **획득 에리어 수** 보수가 별도다.
  현재 seed의 50만~1억점/코인 26행은 원본 표로 검증되지 않았으며 이번에 유지했다.
- 28회부터 개인 달성에 카탄테~프란테 실크 각 1개가 포함된 기록은 확보했다.
  정확한 전 단계 지급 조건을 아직 확보하지 못해 SQL로 설치하지 않았다.
  [기록](https://blog.livedoor.jp/salvare3260/archives/15198724.html).
- 40회 기도 개인 랭킹의 전체 2페이지는 위에 확보했다. 수렵단 랭킹은 미확보다.
- 보너스 타깃은 보수 목록과 별개인 색·시간·대상·배율 표가 필요하다.
  신규 몬스터 우대 같은 회차별 공지만으로 시간을 임의 편성하지 않는다.

## 적용 전 남은 확인

1. 기준 회차: **진설 40회로 확정**.
2. HR/GR 탭과 전체 단계/순위 구간, 아이템 ID·수량 대조.
3. 목록 전송뿐 아니라 조건 검사·수령 응답·중복 수령 방지 구현.
4. 요격전 코인/특별 수렵단방 등 아이템이 아닌 보수의 처리 확인.

한국어 표기는 가능한 부분만 로컬 Ferias sozai/item.js와 대조했다.
문헌은 역사 자료이고, 패킷/지급 형식은 별도로 클라이언트 역분석이 필요하다.

## 수령 프로토콜 보완 (2026-09-21)

대상 덤프: `mhfo-hd.dll.clean.mapped.bin`. 아래는 로컬 역분석 근거이며
서버의 완성된 보수 지급 구현을 뜻하지 않는다.

| 함수 | 확인한 내용 |
| --- | --- |
| `114fde60` | 요청: ACK u32, 조회 플래그 u8, 보수 종류 u8, 개수 u8. 플래그 0에서만 opaque 보상 ID의 u32 배열을 보냄. 1은 조회로 배열 없음 |
| `11535900` | 클라이언트 요청 배열 최대 32개 |
| `11535820` | 응답: 상태 u8, 성공 시 개수 u8, 각 9바이트 = 보상 ID u32 + 아이템 종류 u8 + 아이템 ID u16 + 개수 u16 |
| `103b6ca0`, `103b6bd0` | 조회→클라이언트 로컬 지급→ID 목록으로 수령 확인→재조회. 조회만 했을 때 수령 완료로 기록하면 안 됨 |
| `115359a0` | 실제 수령 요청에는 캐릭터 저장 요청도 동반. 서버에서 별도 인벤토리 지급을 더하면 중복 지급 위험 |
| `11535050`, `11535320` | 매일/개인 달성 목록은 u16 개수 + 각각 15/19바이트 엔트리 |
| `11534a40` | 보너스 타깃은 u16 개수 + 16바이트 엔트리. 기존 빈 목록의 u8 개수는 잘못됨 |

코드에서 조회/수령 패킷을 구분하고, 버려지던 opaque ID를 보존했다.
32개 상한·길이·플래그 검사를 추가했으며, 보너스 타깃 빈 목록과
수령 가능 목록의 응답 길이를 수정했다. 미구현 상태에서 비어 있지 않은
수령 확정 요청을 받으면 지급 성공으로 응답하지 않는다.

**현재 조회 결과는 여전히 빈 목록**이다. 조건 검사·영구 claim 기록·동반 저장의
실패/재전송 처리까지 연결하기 전에는 보수 목록만 먼저 활성화하지 않는다.
이 변경은 기존 저장 데이터 전체를 검증하거나 아이템 조작을 막는 보안 기능은 아니다.
