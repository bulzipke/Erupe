# 요격전 동행자 계약

서버는 클라이언트의 기존 GET/SET 동행자 프로토콜을 지원합니다. 클라이언트 패치, 메뉴 복구 또는 NPC 강제 생성은 포함하지 않습니다. 실제 ZZ 게임에서 동행자가 등장하고 전투에 참여하는지는 별도 인게임 확인이 필요합니다.

## 확인한 네이티브 계약

분석 대상은 `mhfo-hd.dll.clean.mapped.bin` 및 로컬 `mhfsqd.bin`입니다.

| 항목 | 확인 결과 |
|---|---|
| GET `0x178` | 요청: `u32 AckHandle`. 응답: 정확히 12바이트, 상태 바이트 없음 |
| GET 응답 | `u16 NameIndex`, `u16 Voice`, `u16 Weapon`, `u16 Strength`, `u32 AvailableAt`; 모두 big-endian |
| SET `0x179` | 요청: `u32 AckHandle`와 위 네 `u16` 선택값. 시간/가격은 전송하지 않음 |
| ACK | GET buffer ACK, SET simple ACK |
| 이름/목소리 | 이름 인덱스 0..39, 목소리 변형 0..3 |
| 무기 | 0 대검, 1 해머. 무기 비용 각 300 GP |
| 강도 | 0/1/2 (별 1/2/3개); 비용 500/1,000/2,000 GP |
| 총 비용 | 800/1,300/2,300 GP |

GET 빌더 `114fee50`, 파서 `115370e0`, 완료 처리 `115371b0`; SET 빌더 `114fef60`, 완료 처리 `11537220`. 설정 UI `107a92d0`는 `AvailableAt`보다 현재 시각이 작으면 변경을 거절합니다. `107a8a70`은 SET 성공 ACK 뒤에 로컬 GP를 차감하고 저장합니다.

`mhfsqd.bin`의 무기/강도/이름 테이블은 각각 2/3/40행입니다. `101ca120`은 `(3*무기+강도)*2+이름의 성별`로 장비를 선택하므로 인덱스 상한 검사는 필수입니다.

## 서버 동작

- GR 1 이상, 현재 수렵단 소속, 유효한 전가의 장 기간에서만 고용합니다. 운영 phase override는 정상 순환(-1) 또는 전가(2)만 허용합니다.
- 캐릭터 행 → Diva lifecycle advisory lock → 수렵단 membership 행 순으로 잠급니다. 대기 후 DB 시계와 현재 회차를 재확인합니다.
- GP 잔액 부족은 거절합니다. 잔액 차감과 계약 저장은 하나의 트랜잭션이며 저장 실패 시 모두 롤백됩니다.
- 캐릭터당 계약은 하나입니다. 수렵단/회차 변경으로 24시간 변경 제한을 우회할 수 없습니다.
- 24시간 내 SET 재시도는 동일한 선택이어도 실패합니다. 성공 ACK를 반복하면 클라이언트가 GP를 다시 차감하기 때문입니다. GET으로 저장된 계약을 다시 조회할 수 있습니다.
- 24시간은 변경 제한이며 동행 유효기간이 아닙니다. 경과 후에도 GET은 기존 선택과 과거 `AvailableAt`을 유지합니다. 새 고용/변경은 다시 비용을 지불합니다.
- 기간 종료, 탈퇴 또는 수렵단 변경 후 GET은 12바이트 0을 반환합니다.

공식 [PlayStation Blog의 2016-10-28 안내](https://blog.ja.playstation.com/?p=5133)는 GP 고용, 헌터당 1명/최대 4명, 결정 후 24시간 해제·변경 불가를 설명합니다. `101ca120`의 NPC 생성과 `101cac90`의 동행 판정은 `AvailableAt != 0`만 검사하고 현재 시각과 비교하지 않습니다. 현재 시각 비교는 변경 UI `107a92d0` 및 해제/재선택 UI `107a8e80`에 있으므로 자동 만료는 넣지 않습니다.

### 재선택/해제와 sentinel

`107a8d90`에서 호출하는 `107a8e80`은 변경 제한이 지난 경우 로컬 무기/강도를 `0xffff`로 초기화하고 선택 화면으로 돌아갑니다. 이 함수 자체에는 네트워크 호출이 없습니다. SET 빌더 `114fef60`의 직접 호출자는 `107a9210` 한 곳이며, `107a8fb0/107a90d0`에서 무기와 강도를 모두 선택해야 최종 확인 단계에 도달합니다. 따라서 `0xffff`를 서버 계약 해제 요청으로 해석하지 않습니다. 별도의 계약 삭제 패킷은 이 경로에서 확인되지 않았으며, 퀘스트 동행 ON/OFF는 아래 클라이언트 옵션을 따릅니다.

## GP 권위 범위

`CharacterRepository.UpdateGCPAndPact`와 Diva 보수 연계 저장은 GP **절대 잔액**을 저장합니다. 따라서 SET에서 서버가 차감한 뒤 클라이언트가 동일한 감소 후 잔액을 보내면 두 번 차감되지 않습니다.

다만 일반 GP 저장을 서버 권위 원장으로 바꾸지는 않았습니다. 클라이언트가 다른 절대 잔액을 제출하거나, ACK 유실 이후 오래된 잔액을 저장하는 문제까지 이 계약 기능만으로 막지는 못합니다. 계약 차감 자체의 원자성/중복 방지와 기존 GP 저장의 신뢰 경계는 별개입니다.

## ZZ 지원 범위와 게임 내 확인

현재 덤프의 출발 처리 `115766b0`는 조건을 만족하면 GET 후 `101ca120`으로 NPC 구조체를 생성하고 `11572770`으로 전달합니다. `DAT_11a3efb6`는 버전 비활성 플래그가 아니라 `mhf.ini`의 `OPTION/GK_ACCOMPANY` 값입니다(`1158e380`, `10946b40`). 0이 동행 ON이며 OFF 처리는 클라이언트가 수행합니다.

이 경로가 남아 있다는 사실만으로 모든 ZZ 메뉴/퀘스트에서 실제 NPC가 등장한다고 단정하지 않습니다. 테스트 시 ① 유효한 요격 퀘스트/동행 ON ② GP 감소 ③ 재접속 GET 복원 ④ NPC 출발/전투 ⑤ 중복 변경 거절을 함께 확인해야 합니다. 미지원 퀘스트에 NPC를 강제로 삽입하지 않습니다.
