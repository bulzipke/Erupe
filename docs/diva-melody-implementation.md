# 선율(歌迎の調べ) 서버 구현

2026-09-23. 이 문서는 `diva-melody-exchange.md`의 당시 활성화 보류 상태를
현재 구현으로 갱신하는 후속 문서입니다. 운영 DB·클라이언트 파일은 수정하지 않았습니다.

## 원본과 역분석 근거

- [최종 공식 매뉴얼](https://web.archive.org/web/20191218054658id_/http://cog-members.mhf-z.jp/sp/manual/page399.html):
  개인 달성 보수로 획득하며 계정 내 캐릭터 획득량은 합산하지 않고 최댓값을
  공유합니다. 소비도 공유하며 가영의 장 종료 시 잔액은 소멸합니다.
- `mhfo-hd.dll.clean.mapped.bin` `11501860` → `114ed0b0` → `114ed300` →
  `115372b0`: GET/USE는 simple ACK의 4바이트 **big-endian 정수** 중 하위
  1바이트를 잔액으로 사용합니다. 10은 `00 00 00 0A`입니다.
- `107a3850`: 요격전 수령 후보에 item type 28/29를 포함합니다.
  `107a3b70`은 이 두 유형을 인벤토리·GP에 지급하지 않으며,
  `107a3c20`은 수령 ID를 `ACQUIRE_UD_ITEM` type 6으로 확인합니다.
- `107a41b0`: type 28/29의 이름은 메시지 테이블 `DAT_1e77dccc+0xE28`
  의 `+0x20`/`+0x24`를 사용합니다. 로컬 원본 `mhfpac.ptrmap.csv`의
  slot 3624 → 1546304, `mhfpac.csv`의 1546336은
  `特別猟団部屋の利用権`, 1546340은 `歌迎の調べ`입니다.
  따라서 **type 29는 선율**, 28은 특별 수렵단방 이용권으로 확정했습니다.
- `107bb270`: USE 성공 결과에서만 선택한 서버 상점행의 소재·수량을
  `10ba1280`으로 클라이언트에 지급합니다. 서버는 추가 소재를 지급하지 않습니다.

## 적용한 획득표

GR 개인 달성 표에 선율의 누적 최고 획득량을 표시하고 별도 type-29 수령
영수증을 제공합니다. 목록 조회나 점수 상승만으로 잔액을 만들지 않습니다.
실제 해당 영수증을 수령할 때 영수증 확정과 계정 월렛 갱신이 한 DB
트랜잭션으로 이루어집니다. 로컬 아이템 저장이 없는 유형이므로 SAVEDATA를
기다리지 않습니다. 소재/GP의 기존 저장 확정 방식은 유지합니다.

| 개인 요격 점수 | 최대 선율 | 자료 구분 |
| --- | --- | --- |
| 14,000 / 34,000 / 54,000 / 75,000 | 1 / 2 / 3 / 4 | [19회 당시 비교표](https://capcir.blog.fc2.com/blog-entry-1530.html)에서 유지된 것으로 추론; 40회 직접 확인 아님 |
| 84,000 | 5 | 기존 38회 화면에서 추론 |
| 94,000 / 104,000 / 114,000 / 124,000 / 134,000 | 6 / 7 / 8 / 9 / 10 | 기존 40회 직접 확인 화면 |

HR 원본 획득표는 미확보이지만, 사용자가 승인한 [서버용 HR 표](diva-hr-melody-restoration.md)를
추가했습니다. GR 기준 점수의 50%인 7,000~67,000점에서 누적 최고치 1~10개입니다.
GR/HR의 획득량을 더하지 않고 계정 내 최고치만 공유합니다. 교환에는 해당
캐릭터의 현재 수렵단에 실제 특별방 자격이 필요합니다.

특별방 type 28 안내는 HR/GR 표에 각각 1구역으로 표시합니다. 기존의
실제 구역 기반 자동 해금은 유지하고 별도 가짜 아이템·영수증은 발급하지
않습니다. 따라서 별도의 ‘이용권 수령’ 팝업을 만드는 구현은 아닙니다.

## 교환 상품

`ENUMERATE_SHOP` type 9 / shop 0에 공식 목록의 76종을 제공합니다. 다른 상점
type 8의 노래스킬·GP 상품은 변경하지 않습니다. 기존 임의 type-9 DB 상품을
합치지 않고 검증된 코드 목록을 사용합니다.

- 제스·리아루오·레우아스·레이레스 검/사 장식품 총 40종: 1개 = 선율 1.
  [당시 4종 교환 설명](https://ameblo.jp/irwrhk/entry-12437349748.html)과
  [공식 40회 교환표](https://web.archive.org/web/20191215192228id_/http://members.mhf-z.jp/contents/regular_event/diva/change_item.html), Ferias ID 대조.
- 카탄테 실크 `0x3696`, 리칸테 실크 `0x37DB`: 각각 1개 = 선율 2.
  [당시 교환 설명](https://mhf-akia.blog.jp/archives/1066245293.html).
- 나머지 외장권 26종·실크/천 8종을 추가했습니다. 품목·비용·ID는 대조했고,
  개별 수량 직접 확인과 동일 계열 1개 추론은 [복원 근거표](diva-melody-catalog-restoration.md)에 구분했습니다.

## 저장·경계·보안

### 교환 품목 미리보기와 구매 자격 분리

2026-09-23 후속 수정: 요격전 메뉴의 **가영 특별 아이템 교환 품목**은 실제
구매가 아니라 선율 상품표 미리보기입니다. 기존 구현은 이 목록에도 가영 기간·
특별방 자격 검사를 적용해 전가의 장에서 0행을 반환하는 문제가 있었습니다.
검증된 76종 목록은 그대로 재사용하며 새 보수나 임의 비용은 추가하지 않습니다.

- 미리보기 `107a4b20 → 107a4a20`과 실제 상점 `107bbcb0`은 모두
  `11528fe0(9,0)`을 호출합니다. `ENUMERATE_SHOP`의 type 9 / shop 0,
  Limit 512와 동일한 부가 필드를 사용하며 별도 미리보기 플래그는 없습니다.
- `107a4b80`의 헤더는 `mhfpac` slot 1606852의 `アイテム名`,
  1606856의 `必要コスト`입니다. `107a4c70`은 서버가 보낸 아이템 ID로
  클라이언트 이름을 찾고 비용에 해당하는 선율 아이콘을 그립니다.
  서버가 한글 아이템명을 별도 문자열로 전송하는 방식이 아닙니다.
- `107a5380`은 페이지 이동·뒤로가기만 처리합니다. 카탈로그 뒤에
  `107a4aa0`이 선율 잔액을 조회하지만 목록 보기로 선율을 얻거나 쓰지는 않습니다.
- 따라서 활성 ZZ 세션의 정규 9/0 목록 조회에는 구매 자격과 관계없이 76종을
  반환합니다. 목록 자체는 DB를 조회하거나 회차·보수·월렛을 만들지 않습니다.
  요청 Limit, 잘못된 shop ID, 비활성/구버전/인증 전/시각 강제 세션 제한은 유지합니다.
- 실제 `USE_UD_SHOP_COIN`에서만 기존 실제 기간·현재 정회원·1에리어·
  소유 계정·잔액 검사를 수행합니다. 미리보기를 열었다고 교환이 허용되지 않습니다.
- 네이티브 카탈로그는 type/shop별로 캐시됩니다. 서버 업데이트 후에도 빈 목록이
  남으면 클라이언트를 완전히 종료하고 다시 실행해 확인해야 합니다.

이는 수렵단 **티켓** 추가 교환 메뉴와 별개입니다. 티켓 상점의 미확정 경로를
이번 선율 미리보기 수정으로 구현 완료한 것으로 간주하지 않습니다.

### 잔액 및 실제 구매

- `(user_id,event_id)`별 `earned`, `spent` 저장. `earned=max(기존,수령한상한)`,
  `balance=earned-spent`입니다. 6개 획득 후 2개 소비, 다른 캐릭터가 10개
  상한 수령 시 잔액은 **8개**입니다. 중복 수령으로 소비량을 초기화하지 않습니다.
- 0059는 기존 보수 receipt에 검증된 type 29를 허용하며 새 월렛만 추가합니다.
  기존 소재·점수·수령 기록을 재작성하지 않습니다. 과거 사용 기록은 만료 후에도
  보존하되 읽기·교환은 0/거절입니다. 고아 회차나 뒤의 무참여 회차 때문에
  더 오래된 월렛을 되살리지 않습니다.
- 요청 캐릭터의 실제 소유 계정 확인, 현재 실제 요격전 회차, DB 잠금 후
  서버 시각, 가영 기간, 현재 가입 수렵단과 실제 1구역 확보를 검사합니다.
  설정만 가영으로 바꿔 가짜 권한·선율을 만들지 않습니다.
- 동일 계정의 여러 캐릭터·채널 차감은 DB 행 잠금으로 직렬화하고 잔액은
  0 미만/최고 10 초과가 되지 않도록 스키마와 코드에서 제한합니다.
- 가영 종료 후에도 소재 보수의 기존 수령 기간은 유지됩니다. 만료 선율만
  미수령 목록에서 제외하여 소재 수령을 막지 않으며, 영수증을 가짜로 완료
  처리하거나 삭제하지 않습니다.

## 원본 패킷의 한계와 실제 게임 확인

USE 요청은 비용 1바이트만 보내며 아이템 ID·구매 UUID·회차가 없습니다.
따라서 정상 연속 구매와 재전송을 완벽하게 구분할 수 없습니다. 각 성공
요청마다 잔액이 실제로 차감되며, 같은 요청이라고 성공 ACK를 재전송하여
클라이언트 지급만 추가 실행시키지 않습니다. 변조 클라이언트의 선택 아이템
내용이나 응답 직후 저장 전에 끊긴 경우까지 서버가 원자적으로 보장하지
못합니다. 서버에서 또 아이템을 지급하는 해결책은 사용하지 않았습니다.

ZZ 원본 프로토콜에 한정합니다. 서버 테스트와 별도로 실제 게임에서
type-29 표시·수령 후 잔액 갱신, 1/2선율 교환, 계정 내 캐릭터 전환,
포치 부족 거절, 특별방 입장 및 기간 종료를 확인해야 합니다.
