# 요격전 보너스 퀘스트 일정

2026-09-22. 서버 응답만 수정합니다. 클라이언트 패치, 운영 DB 변경 및 배포는 포함하지 않습니다.

## 적용 내용과 자료의 한계

기존 `GetUdTacticsBonusQuest` 응답에 들어 있던 **2019-11-13~20의 20개
퀘스트·배율·순서**를 그대로 유지하면서, 날짜를 현재 전가의 장 개최일로 옮깁니다.
이 날짜는 40회 전가의 장(2019-12-04~11)과 다릅니다. 39회 개최 시기에
해당하지만, 기존 응답의 원본 캡처 출처까지 입증하지는 못했습니다.
따라서 이것은 **기존 Erupe 운영표 재사용**이지 40회 공식 보너스표 복원 완료가 아닙니다.

- 전가의 장 시작일의 UTC+9 22시부터 시작합니다.
- 이후 8시간 간격, 2시간씩으로 기존 22~24시 / 06~08시 / 14~16시를 유지합니다.
- 실제 회차 시작·종료 시각 밖의 구간은 잘라냅니다. 자정에 시작하는 강제
  전가의 장은 마지막 구간이 잘리거나 제외되므로 20개보다 적을 수 있습니다.
- 같은 회차이면 재접속·서버 재시작·자정 경과로 퀘스트 순서나 날짜가 바뀌지 않습니다.
- 전가의 장 이외에는 보너스를 제거합니다. 기도의 장 `DivaBonusRandom`과 별개입니다.
- 퀘스트를 새로 DB에 등록하거나 배포 제한을 변경하지 않습니다.
- 대상 파일과 event_quests 등록은 기존 요격전 퀘스트 배포 경로를 사용합니다.
- 새 동적 응답은 `ZZ`에서만 사용합니다. 미검증 구버전은 빈 목록을 반환합니다.

## 클라이언트 분석 근거

읽기 전용 Ghidra 분석 대상: `mhfo-hd.dll.clean.mapped.bin`.

| 함수 | 확인한 내용 |
| --- | --- |
| `0x114ffa90` | `MSG_MHF_GET_UD_TACTICS_BONUS_QUEST` 요청, opcode `0x185`. |
| `0x115373c0` / `0x107a6e20` | 수신 버퍼 0x202바이트 할당, 요청 최대 길이 0x201. |
| `0x11537320` | `u8 count` + `{u16 questID, u32 start, u32 end, u16 percent}` 12바이트 레코드. 저장 공간 최대 32개. 미사용 뒷부분을 초기화하지 않음. |
| `0x107a6e70` | 정오 기준 날짜 화면에서 32개 슬롯 전체를 검색함. |
| `0x1039e610` | `start <= clientTime <= end`인 슬롯만 활성화. |
| `0x103a24b0` | 현재 퀘스트와 시간이 일치하는 슬롯을 찾아 `base * (percent - 100) * 0.01`을 추가 보너스로 계산. |
| `0x103a16c0` | 요격전 점수 계산 과정에서 위 보너스 함수를 호출함. |
| `0x103a1620` | 보너스 저장값 `DAT_1e892b40`을 포함해 요격전 총점을 합산함. |

예를 들어 패킷 값 `600`은 **600포인트 지급**이 아니라 **기준 점수의 총 6배**입니다.
다른 보너스 항목 전체를 6배 한다는 뜻도 아닙니다. 계산은 순정 클라이언트가 담당하며,
서버는 전송받은 `TacticsPoints`를 다시 곱하지 않습니다.

클라이언트가 항상 32칸을 검색하므로 **빈 목록도 count=32 + 32개의 0 레코드**로
보냅니다. 정상 목록도 남은 칸을 0으로 채웁니다. 한 바이트 `count=0`만 보내면
이전 회차의 보너스가 캐시에 남을 수 있습니다. 응답은 385바이트로 버퍼 이내입니다.
내부 일정은 종료 시각 미포함으로 처리하고, 전송 시 종료에서 1초를 뺍니다.
기존 hex 문자열 뒤의 SQL 문장·잡다한 바이트는 프로토콜 필드가 아니므로 제거했습니다.

## 검증 및 남은 확인

- 회차별 날짜 이동, 순서·배율 유지, 강제 단계의 경계 잘림, 타임스탬프 overflow를 테스트합니다.
- 32칸 캐시 모델에서 짧아진 목록과 비활성 응답이 이전 보너스를 지우는지 테스트합니다.
- 기도·가영·비활성 단계, 회차 없음·만료·미시작, 저장소 오류, 구버전 클라이언트를 테스트합니다.
- 클라이언트가 계산해 보낸 1,000점이 서버에서 10,000점으로 재증가하지 않는지 테스트합니다.
- `go test -race ./server/channelserver -run 'Test(DivaTacticsBonus|HandleMsgMhfGetUdTacticsBonusQuest)' -count=1 -timeout=3m` 통과.
- 실제 게임에서 정오 이후 목록 표시와 해당 시간·퀘스트의 결과 점수 확인은 별도 필요합니다.
- 40회 공식 날짜별 대상·배율은 아직 미확보입니다. 확보되면 운영표만 교체할 수 있습니다.

40회 날짜 대조 자료: [당시 전가의 장 기록](https://byuwasoku.hatenablog.com/entry/2019/12/05/120303).
해당 글에서 날짜별 보너스 퀘스트 전체 표는 확인하지 못했습니다.
