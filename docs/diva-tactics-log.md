# 요격전 전황 로그

`GET_UD_TACTICS_LOG`의 빈 응답을 실제 지도 원장 조회로 교체했습니다. 운영 DB를 변경하거나 과거 이력을 합성하지 않습니다. 조회자는 현재 가입이 승인된 수렵단의 최신 실제 요격 회차만 조회합니다. 요청에는 수렵단 ID 자체가 없습니다. 이적하면 이전 수렵단 캐시는 빈 응답으로 교체됩니다.

## 확인한 클라이언트 형식

검증 대상: `mhfo-hd.dll.clean.mapped.bin` (ZZ), read-only Ghidra 분석.

- 송신 `114fed40` / `11537030`: opcode `0x175`, 최대 응답 `0x23f1` 바이트.
- 수신 `11537070` → `11536f50`: `u8 count` 다음 46바이트 레코드. 최대 200개. unused 캐시는 클라이언트가 0으로 지웁니다.
- 각 레코드: `u8 kind`, `u8 branch`, `u32 character`, `char name[32]`, `u32 value`, `u32 Unix timestamp`. 다중 바이트 정수는 big-endian입니다. status 바이트나 200개 고정 padding은 없습니다.
- `103a6590`은 서버가 준 순서대로 표시하며 UTC+9 시간을 사용합니다. `103b9020`에서 타입별 실제 메시지 포맷을 읽습니다.

| kind | native 의미 | 서버 원장 |
|---|---|---|
| 0 | 헌터의 획득 포인트 | 해당 지도에 유효하게 귀속된 퀘스트 결과 |
| 1 | 누적 획득 에리어 수 | 실제 정산된 에리어 획득 기록 |
| 2 | 헌터의 개인 누적 포인트 돌파 | 해당 회차의 개인 요격 점수 원장, 매 10,000점 기준 |
| 3 | 몬스터 기세 증가 | v3 시간 침공으로 실제 필요점수가 증가한 정각의 기록 |
| 4 | 보물 발견 | 실제 획득한 분기 에리어 기록 |
| 5 | 연/월/일 구분 | UTC+9 날짜별 표시 헤더 |
| 6 | 헌터의 N번째 분기 획득 포인트 | 원래 출발 지도에 귀속된 분기 결과 |

종류 3은 [승인된 v3 운영 규칙](diva-map-progressive-operation.md)의 실제 침공에만 연결합니다.
`103b9020`의 고정 문구를 사용하며 이름·헌터 ID·분기·수치는 0입니다. 실패한 추첨에는 기록하지 않습니다.
종류 2는 `103b9104..103b9146`의 실제 기계어에서 종류 0과 동일하게 이름과
수치를 sprintf 인자로 넘기는 것을 확인했습니다. `103b8f90`은 헌터 ID,
`103b8f30`은 이름, `103b8fc0`은 수치를 읽으며 메시지 테이블의 `+0x44` 문구를
사용합니다. 분기 번호는 0입니다. 디컴파일만 보면 가변 인자 중 수치가 생략되므로
기계어의 두 PUSH와 16바이트 스택 복원까지 대조했습니다.
원본 문구는 클라이언트 내장 문구를 그대로 사용하며 서버가 문구를 덧붙이지 않습니다.
보물 발견 로그에는 보물 내용이나 미발견 좌표를 보내지 않습니다.

## 개인 누적 돌파 기준 (서버 운영 대체값)

- 같은 회차의 실제 `diva_interception_runs` 점수가 **10,000 / 20,000 / 30,000 / …**에
  도달할 때마다 종류 2를 표시합니다. 10,000점 간격은 원본 미확보 상태에서 정한
  서버 전용 표시 정책입니다. 보수 지급 조건이나 저장된 점수는 바꾸지 않습니다.
- 개인 누적이므로 이적 전 점수도 합산하지만, 돌파 로그는 그 기준에 도달한
  결과 원장의 수렵단에만 귀속됩니다. 15,000점에서 이적하고 5,000점을 얻었다면
  새 수렵단에는 20,000점 돌파만 보이며 이전 수렵단의 10,000점 로그는 보이지 않습니다.
- 포인트 원장을 `(submitted_at, run_key)`로 정렬하여 누적합니다. 같은 시각의
  결과도 UUID로 순서를 고정합니다. 한 결과에서 여러 기준을 넘으면 기준별로 표시하며,
  동일 시각·캐릭터의 돌파 로그는 높은 기준부터 나옵니다. 날짜·시각은 그 결과의
  서버 제출 시각입니다. 조회 시각 이후 원장은 누적과 로그 모두에서 제외합니다.
- 지도에 실제 반영된 `credited_points`가 아니라 **검증을 통과하여 개인에게 쌓인 점수**를
  사용합니다. 지도의 초과 점수 폐기나 잠긴 분기 때문에 지도 적립이 없어도 개인
  점수 원장에 실제로 존재하는 획득분은 개인 누적에 포함됩니다.
- 별도 카운터·지급 기록을 추가하지 않고 기존 원장으로 계산하므로 재접속·중복
  보고·동시 조회에 따른 새 알림이나 점수가 추가되지 않습니다. 현재 회차에 이미
  존재하는 원장도 조회할 수 있지만, 이전 회차를 가져오거나 가짜 기록을 삽입하지 않습니다.
- 계산은 정밀 숫자형으로 하며 클라이언트의 signed 32비트 표시 상한까지만 기준을
  만듭니다. 최근 200개 돌파 결과에서 결과당 최대 최근 200개 기준만 확장한 뒤,
  다른 전황 로그와 합쳐 최종 200행으로 제한합니다. 날짜 헤더도 이 제한에 포함됩니다.

## 정책과 안전장치

- 최신 시각부터 최대 200행으로 표시합니다. 이 정렬은 서버 표시 정책이며 원작 서버의 정렬 캡처를 확보한 것은 아닙니다. 날짜 헤더도 200행 제한에 포함합니다.
- 동일 출발 UUID의 재보고는 기존 원장이 멱등 처리하므로 로그도 중복되지 않습니다. 포인트에 보너스를 다시 곱하지 않습니다.
- 포인트 로그는 실제 개인 획득 보고값입니다. 지도 종료 시 초과 점수가 버려져 지도 적립량이 0이 되어도 유효한 기존 보고 자체는 삭제하지 않습니다. 지도 획득 에리어 로그와는 구분합니다.
- 잠긴 분기/지원하지 않는 퀘스트 등 지도 귀속이 거절된 출발은 지도 로그에 넣지 않습니다.
- 분기 번호는 현재 지도가 아니라 원래 출발 지도 스냅샷의 분기 순서로 구합니다. 스냅샷의 회차 버전/시드 검증을 재사용합니다.
- 이름은 현재 DB 이름을 표시하며, 과거 이름의 불변 스냅샷은 아닙니다. CP949 최대 31바이트+NUL로 자릅니다. 클라이언트의 두 번째 printf 처리 때문에 `%`, 제어문자 및 텍스트 제어 구문은 표시 이름에서 제거합니다. DB 이름은 바꾸지 않습니다.
- 기여/보물은 기존 출발·정산 원장을 사용하고, 침공은 0062의 `diva_map_invasions`에 지도 스냅샷과 같은 트랜잭션으로 기록합니다. 삭제 작업은 추가하지 않았습니다.
- 지원하지 않는 클라이언트, 비활성화, 시각 강제 변경, 저장소 오류에는 count=0의 정상 ACK를 반환해 이전 캐시를 비웁니다.

침공 로그에는 신규 SQL 마이그레이션 0062가 필요합니다. 실제 UI 확인은 서버 적용 후 전황 로그 메뉴를 열어 확인해야 합니다.

종류 2 추가에는 신규 마이그레이션이 없습니다. 실제 UI에서는 개인 점수 10,000점
돌파 후 본인·다른 단원 양쪽에서 이름과 10,000점이 정상 표시되는지 확인해야 합니다.
