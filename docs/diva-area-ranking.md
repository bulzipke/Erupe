## 확인한 클라이언트 경로

HD clean mapped dump 정적 분석 기준입니다.

- `114feb00`: 요청 opcode `0x173`, AckHandle(u32), GuildID(u32). 응답 최대 길이 `0xfc9`.
- `107a6200`, `107a8060`: 모두 현재 수렵단 ID(`1e505238`)로 같은 요청을 합니다.
  현재/확정/개인 랭킹·회차·페이지를 지정하는 별도 요청 필드는 없습니다.
- `11536d30`: 응답을 아래 구조로 읽습니다. 성공 본문 앞에 오류 바이트는 없습니다.
- `107a80b0`: count와 관계없이 캐시 100행의 rank를 확인하여 페이지 수를 계산합니다.
- `107a82c0`: 순위·수렵단명·획득 에리어를 그대로 표시합니다. 클라이언트 정렬이나 동률 산정은 없습니다.
  자기 수렵단은 별도 블록으로 표시하므로 100위 밖 순위도 지원됩니다.

| 필드 | 크기 |
|---|---:|
| 자기 순위 | u32 |
| 자기 획득 에리어 | u32 |
| 자기 수렵단명 | 32바이트 |
| 행 수 | u8 |
| 순위 / 획득 에리어 / 수렵단명 | 40바이트 × 행 수 |

정수는 big-endian, 이름은 기존 서버 CP949 인코더로 NUL 패딩합니다.
항상 100행을 보내고 미사용 행을 0으로 채워 과거 캐시를 지웁니다. 총 길이는 4041바이트입니다.
최대 31바이트 이름, 음수가 아닌 signed 32-bit 표시 범위, 중복 수렵단,
자기 블록과 목록의 불일치 등을 검사하며 잘못된 입력은 오류로 반환합니다.
인코더는 전달받은 순위를 유지합니다. DB 순위는 승인된 운영 규칙인 **동률 1·1·3**을
사용하며 동일 순위의 표시 순서만 수렵단 ID로 고정합니다. 원본 동률 규칙 복원이라고 주장하지 않습니다.

## 공개 시각과 연결된 집계

[기존 공식 매뉴얼 조사](diva-interception-map-protocol.md)의 요격전 랭킹 갱신 시각은
04시·12시·20시입니다. 지도 진행의 약 1시간 갱신과 랭킹 공개는 서로 다른 주기입니다.
기도 랭킹의 첫날 18시 예외는 적용하지 않습니다.

`divaAreaRankingCutoff(now, start, end, finalPublication)`은 실제 요격 기간과 최종 공개 시각을
명시적으로 받는 순수 계산기입니다. 승인된 현재 운영 구현은 종료 정산 완료 시점을 최종 공개로 사용합니다.
종료부터 최종 공개 직전까지는 마지막 정기 집계만, 최종 공개 시각부터는 종료 시각까지의
확정 집계를 사용합니다. 지도 원장은 각 시간 경계까지 반영된 획득을 해당 경계 시각으로
기록하고, 공개 스냅샷은 `awarded_at <= 공개 시각`인 원장을 집계합니다. 해당 정각 직전에
보고한 기여는 정각에 반영하며, 정각에 접수된 결과는 다음 구간으로 넘깁니다.
기도 랭킹의 테이블과 일정은 이 집계에 사용하지 않습니다.

구현된 연결 조건은 다음과 같습니다.

- 임의의 포인트 나눗셈이 아닌 실제 지도 에리어 획득 원장을 집계합니다.
- 목록과 자기 수렵단은 같은 회차·같은 cutoff에서 조회합니다.
- 상위 100개 수렵단과 100위 밖 자기 수렵단을 같은 공개 스냅샷에서 조회합니다.
  기도 점수 테이블과 기도 종료 시각은 사용하지 않습니다.
- 매시 정각 지도 정산 뒤 04·12·20시 공개를 생성하며, 마지막 정산 뒤 최종 순위를 고정합니다.
  원본의 정확한 지연 시간을 재현한 것이 아니라 사용자 승인 운영 규칙입니다.
- 회차는 '실제로 시작된 최신 요격 기간'을 기준으로 선택합니다.
  새 기도 회차가 시작됐다는 이유만으로 지난 요격 확정 순위를 다른 회차에 붙이지 않습니다.
- 요청 GuildID만 신뢰하지 않고 인증된 캐릭터의 현재 수렵단 관계를 확인합니다.
- 꺼져 있던 시간의 미정산 구간과 공개 시점을 원장으로 복구하며, 이미 생성한 공개 결과를 뒤늦게 덮지 않습니다.

단위·격리 DB race 테스트로 집계·동시성·공개·이월을 검증했습니다. 실제 클라이언트 순위 화면은
아직 미검증입니다. 클라이언트 패치나 운영 DB 변경·배포는 하지 않았습니다.
