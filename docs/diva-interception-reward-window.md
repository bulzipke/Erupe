# 요격전 미수령 보수의 수령기한

2026-09-21. 개인 요격 보수(type 6)의 수령기한은 **다음 실제 요격전 시작 직전까지**다.
이 문서는 이전 `diva-interception-rounds.md`의 현재 활성 회차만 조회한다는 제한을 대체한다.
첫날 기도 랭킹 갱신 시각 18:00에는 영향을 주지 않는다.

## 회차 선택과 화면

- 기도 단계가 새로 시작해도 직전 요격전의 개인 점수와 미수령 보수를 조회한다.
- 다음 요격전이 시작되면 새 회차로 전환한다. 새 회차에서 점수가 없어도 예전 회차 보수를 다시 보여 주지 않는다.
- 조회 요청에는 회차 번호가 없지만, 보수 확인 ID는 DB에서 전역 유일하므로 기존 패킷 형식으로 이전 회차를 수령할 수 있다.
- `GET_UD_TACTICS_POINT`도 같은 회차의 총점·완료 퀘스트를 반환한다. 다음 요격전부터는 이전 완료 표시가 남지 않도록 기존 255칸 초기화 응답을 유지한다.

## 실제 개최의 근거

0047은 `diva_interception_periods`를 추가한다. 정상 일정/강제 2단계에서 실제 시작 시각에 도달한 요격전만 등록한다.
강제 1·3단계의 가상 요격 날짜나 아직 시작하지 않은 미래 일정은 그 자체로 개최 근거가 아니다.
기존 회차별 요격 기록·type 6 receipt와 실제 시작된 normal/2 앵커는 이관할 수 있지만,
회차가 없는 예전 JSON 누적값은 새 보수의 근거로 복사하지 않는다.
수동으로 강제 단계를 바꾸는 운영은 기존 문서대로 별도 흐름이며, 정상 일정 모드를 권장한다.

## 경계·재전송·다중 서버

- 목록 제공과 미수령 ID 확인은 실제 설정 모드를 받는 요격전 전용 repository API를 사용한다.
- 이벤트 생성과 같은 DB advisory lock을 획득한 뒤 DB 시각으로 lifecycle을 다시 처리한다.
  따라서 handler가 시작 직전에 실행되고 DB 처리가 시작 후로 밀려도 새 개최를 누락하지 않는다.
- 다음 개최부터 오래된 미수령 receipt ID를 직접 보내도 거절한다. 이미 수령을 완료한 동일 ID는 중복 지급 없는 재시도로 허용한다.
- 마감 전에 정상적으로 claim을 확인하고 세션에 대기시킨 수령은 뒤따르는 SAVEDATA/GP 저장으로 완료할 수 있다.
  저장 완료 전 단순 목록 조회나 claim 자체만으로 소비 처리하지 않는 기존 원자 저장 정책은 유지한다.
- 기존 미수령 receipt의 아이템·수량 snapshot은 해당 수령 기간 동안 보존한다. 이후 보수표에서 행이 빠져도 이미 제시한 보수의 내용을 변경하지 않는다.
- 1회 응답은 원본 클라이언트 한도인 32개이며, 미수령 항목을 안정적인 ID 순서로 나누어 반환한다.

## 확인한 native 흐름과 남은 검증

`11536900`은 GET_TACTICS_POINT 총점을 클라이언트 전역에 저장한다.
`107a3c20`의 type 6 수령 처리에는 직접적인 총점·phase 검사가 없고 서버가 반환한 보수 목록 개수로 처리한다.
상위 메뉴도 정적으로 확인했다. `107bc530`은 기도 기간에 disabled mask `0x7`을 적용해
인덱스 0~2만 막으며, 보수 그룹인 인덱스 4는 허용한다. `107bd9e0`의 마스크 검사 뒤
`107bc870` → `107bc6c0 case 4` → `107a4f70(1)` → `107a49a0(0)` → `107a3c20(type 6)`으로
연결된다. 하위 generic 메뉴 처리 `107328b0`/`10732920`에도 기간 제한은 없다.
따라서 다음 기도 기간의 상위 메뉴가 수령을 막는 구조는 아니다.
실제 게임에서는 이전 요격전 → 다음 기도 단계 → 미수령 보수 조회/수령·저장 →
재접속 → 다음 요격전 초기화를 검증해야 한다. 번역된 메뉴 명칭·실화면 검증은 아직 하지 않았다.
이번 변경은 클라이언트 DLL 수정, 운영 DB 적용, 서버 배포를 포함하지 않는다.
